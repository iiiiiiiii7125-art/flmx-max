# FLMX 1.3.7 发版说明

R3 全量审计修复版：以 1.3.6 为基线完成新一轮「基线 → 12 域并发审计 → 交叉复核裁定 → 13 批修复 + 文档批 + 基建批 → 集成全量回归 → 发版门两轮真机复验（含定点修复）」循环，本版是该轮的全部修复成果。用户已预授权按交叉复核推荐口径执行（含全部行为变更项）。本轮新增 P1 归零（三轮轨迹 P1：3 → 2 → 0），残余集中于「修复只落一面/一层/一方向」的同族收尾。

## 修复内容（按批次）

### 批次 1 · netguard 消费侧残余收口

- 导入与探测共用的硬拒策略补消费 Reserved/Multicast 分类：`0/8` 非零、224/4、240/4、198.18/15 等字面量在导入期与拨号前双双拒绝，与仓库「0/8 整段拦截」口径及其余判定面一致（R3X-010）。
- 隧道质量探测目标与延迟测试点目标（原为第六套判定、仅格式校验）保存时接入 netguard：元数据/回环/localhost/整数/十六进制/NAT64/6to4 形态均被拦截；存量坏目标在下发时跳过并告警，节点侧 TcpPing 再加一道纵深校验（R3X-011）。

### 批次 2 · SS2022 密钥格式校验（O-1 落地）

- **P2**：导入解析收口至 `validateProxyCredentials` 一处，覆盖四种分享格式与三个导入入口：SS2022 密钥须为 base64 解码后 16/32 字节，不合规单条拒绝并提示，其余节点不受影响（R3X-008，见 BC-R3-01）。
- 解码容忍 Std/RawStd/URL-safe/RawURL 四种 base64 形态，避免合法 URL-safe 密钥被误拒（硬条件，表驱动矩阵 96 子项回归）；旧格式编辑分支补同点校验；存量不迁移，靠渲染略过与同步报错自然淘汰。

### 批次 3 · 计费零倍率兑现与 nft 限速警告

- **P2**：计费消费层 `GetFlowUploadForwardMetas` 的 `<=0 → 1` 归一化限定为「隧道行缺失」兜底，行存在且倍率=0 时保留 0——TrafficRatio=0 隧道真正零计费（原始流量计数仍保留、与配额入账分离），兑现 1.3.6 BC-R2-03 承诺（R3X-003，见 BC-R3-07）。
- nftables 同步路径补限速/连接数警告：带有效限速设置的转发在 nft 模式下同步时给出明确警告（此前静默不生效），禁用/零速不误报；forward.md 补 nft 模式限制披露（R3X-019，见 BC-R3-08）。

### 批次 4 · 白名单刷新漏斗层统一接线

- **P2**：forwardUpdate 切隧道路径补白名单刷新与 RemoteAddr 重算（切隧道后新落地 allow 含本机拨号地址、旧落地收回）（R3X-002）。
- 同批补齐同族三面：停用组/撤销授权清转发后落地 allow 收回（R3X-016）、删节点（单删/批删/链式）后其他入站 allow 中该节点地址消失（R3X-017）、nft pending 终删由 job 在真正删除时刷新（pending 窗口内不提前刷新）（R3X-018）。E 域全集对账 37 行回勾表漏接归零。

## 行为变更（逐条附可转发通知文案）

1. **BC-R3-01 SS2022 密钥格式校验（R3X-008）**：导入/订阅更新校验 SS2022 密钥格式，不合规单条拒绝并提示，其余节点不受影响；存量异常节点在 sing-box 订阅中被略过。配合发版门 GATE-F1 的渲染规范化，存量非规范拼写的合法 key 拉取即自愈（见升级注意事项）。
> 导入与订阅更新时，SS2022（2022-blake3-*）节点的密钥会校验格式（base64 解码后须为 16/32 字节），不合规的单条节点会被拒绝并提示原因，其余节点不受影响；此前已导入的异常节点请重新导入。
2. **BC-R3-02 保留/组播段拒绝（R3X-010）**：导入与探测拒绝保留/组播段地址（0.0.0.0/8 非零、组播等）。
> 节点导入与连通性探测不再接受保留地址段（如 0.x.x.x、组播地址），这类地址的节点会被拒绝；公网/内网/运营商 NAT 地址不受影响。
3. **BC-R3-03 探测/延迟目标拦截（R3X-011）**：隧道探测目标与延迟测试点目标保存时拦截元数据/回环地址，存量坏目标下发时跳过并告警。
> 延迟测试点和隧道探测目标不能再填云元数据或本机回环地址；此前已保存的这类目标会被跳过并在日志中提示。
4. **BC-R3-04 存量停用组追溯撤销（R3X-004）**：存量停用分组的组建授权在首次同步/保存时追溯撤销，兑现 1.3.6 已承诺口径。
> 1.3.6 已说明的『停用分组收回组授权』现起对升级前就已停用的分组同样生效：首次同步或保存该分组时，其组建授权会被收回并清理对应转发，手工分配的授权不受影响。
5. **BC-R3-05 备份恢复授权口径一致（R3X-005）**：备份恢复的分组/权限结果与运行时授权口径一致（成员替换同步撤销、停用组不落授权、同名组权限跟随恢复后的组）。
> 用备份恢复分组与权限后，授权结果与在界面上手动调整一致：被移出分组的成员不再保留组授权，停用分组不会带入授权。
6. **BC-R3-06 中转分配跟随恢复（R3X-023）**：备份恢复后入站中转分配跟随恢复后的中转行，不再静默失效。
> 备份恢复后，已分配给用户的中转线路会跟随恢复后的线路继续有效，不再出现分配还在、订阅里线路消失的情况。
7. **BC-R3-07 零倍率真零计费（R3X-003）**：TrafficRatio=0 的隧道真正零计费，兑现 1.3.6 BC-R2-03。
> 倍率设为 0 的隧道现已真正按零计费执行（1.3.6 说明中已承诺）；此前按 1 倍扣费的 0 倍率隧道请复核配额。
8. **BC-R3-08 nftables 限速警告（R3X-019）**：nftables 模式下限速/连接数设置给出明确警告（此前静默不生效）。
> nftables 转发模式不支持限速和连接数限制，保存了这类设置的转发在同步时会给出警告提示（此前为静默不生效）。
9. **BC-R3-09 演示站录制补齐（R3X-009/031/032）**：演示站录制补齐（仅演示面，无产品行为变更，列入备查）。
> 在线演示站的监控详情、订阅流量等页面演示数据已补齐。

## 升级注意事项

- **SS2022 存量自愈与自查（BC-R3-01 + GATE-F1）**：存量以 RawStd/URL-safe 等非规范拼写保存的合法 SS2022 key 无需任何操作，升级后拉取订阅时渲染层自动规范化为标准形态，sing-box/Clash 均可正常加载；只有解码后字节数不合规（16/32 之外）的真坏 key 才需要按 BC-R3-01 重新导入。SIP002/SIP023 多段 key 在 Clash 面已逐段归一；sing-box 面对多段 key 维持保守略过口径（解除与否留 R4 裁定，见发布报告遗留登记）。
- **零倍率隧道复核（BC-R3-07）**：1.3.6 及更早版本中，倍率=0 的隧道实际按 1 倍扣过配额；本版起真正零计费。此前被扣的配额不自动回补，请复核 0 倍率隧道的配额用量与用户额度。
- **存量停用组追溯（BC-R3-04）**：升级前已停用的分组会在升级后首次同步或保存时追溯撤销组建授权并清理其转发；只影响分组发放的授权，手工单独授予不动。不希望触发追溯的，请先核对成员与转发清单再做同步/保存动作。
