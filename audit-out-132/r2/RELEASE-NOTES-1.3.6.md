# FLMX 1.3.6 发版说明

R2 全量审计修复版：以 1.3.5 为基线完成新一轮「基线 → 12 域并发审计 → 交叉复核裁定 → 12 批修复 + 补批 + 文档批 + 基建批 → 集成全量回归 → 发版门真机复验」循环，本版是该轮的全部修复成果。用户已预授权按交叉复核推荐口径执行（含全部行为变更项）。

## 版本概览

- 审计总账（R2-X-ledger 去重合并后）：**P0 = 0 / P1 = 2 / P2 = 19 / P3 = 28，合计 49 条，49/49 全部关闭**。B 域补交的两个候选均不立案，未占用补号。
- 修复集成：`integrate-r2 @ 3c53ced`，在 1.3.5 基线 `1672dc4` 之上共 70 个提交（含 12 个计划批、补批 13/14、文档批、基建批、合并提交与集成登记）；合入 main 时零丢提交。
- 全量回归：go-backend、go-gost、go-gost/x 的 build/vet 通过；前端 `tsc --noEmit` 与 `vite build` 通过；脚本 proxy 套件通过；check-doc-consistency PASS。集成终轮中仅保留两项已定性且非本轮引入的红：本沙箱 fake-IP DNS 导致的 health 单格环境红，以及 check-contract-fields 的 C7 基线既存 8 条（详见升级注意事项与发布报告）。
- 发版门真机复验：**11/11 项 + 补充 3/3 全部 PASS**，包括两条 P1 的真机双向坐实、PG 三条契约实跑、缓存全表面五面与存量计数对账。
- 行为变更共 13 条单列于下节（BC-R2-01…BC-R2-13），另有 1 条对 1.3.5 BC-13 的口径纠正；每条均附一行可直接转发的通知文案。

## 修复内容（按批次）

### 批次 1 · IP 判定集收口（netguard）

- **P1**：普通用户转发目标改走统一 netguard 分类器，云元数据、169.254/16 链路本地段、未指定地址与 NAT64 内嵌同类地址硬拒，普通转发不再缺拨号层兜底（R2X-001）。
- 导入主机、联邦传输/诊断/角色目标、SecureFetch、通知出站与监控目标共用同一判定集；导入别名逐条报错，监控判定改为硬拒层先于 allowlist，通知改 pinned-dial（解析 → 校验 → 拨已校验 IP，保留 SNI/Host 并逐跳复检）（R2X-005/006/026/027/043/044）。

### 批次 2 · 幂等族收口

- 幂等缓存升级为在途预留状态机：同键并发第二请求等待回放、接管失效预留或收到 409「处理中」，不再并发重复执行（R2X-003）。
- 缓存键加入用户与 scope（method + path）维度；后端补齐创建面，面板 12 个创建表单自动携带会话级 Idempotency-Key（R2X-004/032，另见口径纠正）。

### 批次 3 · 计费与计数完整性

- 流量 seq 推进改判 `RowsAffected`：0 行以哨兵错误整事务回滚，同 seq 并发/重放不再双入账（R2X-011）。
- 入站计数首采与 epoch 变化改只推进基线、不把历史累计值计入，与订阅/转发管线统一（R2X-033）；realm 限速警告改以「规则存在且速度 > 0」为有效性谓词（R2X-034）。

### 批次 4 · WS 会话上限原子化

- 每用户会话上限改锁内预留：并发连接下恒不超过上限，原先 40 并发可突破到 11 的竞态关闭；既有会话上限测试断言未改（R2X-022）。

### 批次 5 · Snell 与订阅渲染 / 性能

- **P1**：导入 Snell 按客户端分面设版本域——sing-box 出站只接受 {4,6}、Clash 按 1–4（5 归一为 4）、Surge 按 1–6；越界/缺失在导入期报错，sing-box 订阅对不适用节点略过，不再毒化整份配置（R2X-002）。
- Snell v6 unshaped mode 往返保留；订阅脚本 goja Program 按哈希缓存（VM 仍逐请求新建，输出不变）；Regions/Protocols 未知值过滤、RelayIDs 超 1000 明确报错（R2X-023/024/025）。

### 批次 6 · 内核版本门与入站更新 presence

- VLESS ENC 拨号侧版本门补齐保存校验、下发整单拒绝与换版扫描三面，与服务端及 Snell 拨号门同口径（R2X-007）。
- 更新入站时 EncryptionSecret、Reality 密钥与 ShortIDs、Listen、UUID、Password 留空改回填保留，不再静默轮换；显式 regenerate 与创建路径不变（R2X-030）。

### 批次 7 · 分配引用完整性 / 分组 / 事务

- 分配类入口统一存在性校验并扩围至组与隧道分配面：任一 ID 不存在整体报错、零落行（R2X-012/036）。
- 分组停用真正撤销组建授权并清理其转发，重新启用按成员关系补发；删 user_tunnel 先清 grant 台账；userTunnelRemove 对已不存在目标改幂等成功回执（R2X-013/035/048，见 BC-R2-02）。

### 批次 8 · 备份导入保真与引用

- 悬空限速、入站来源/出站与 grant 组键等附属引用改剥离/改写并计入 ImportWarnings，不动导入段序、不跳整行（R2X-014/015/037/046）。
- 零值写回泛化修复 TrafficRatio=0 被默认值吞掉的问题，恢复后保持零倍率（R2X-016，见 BC-R2-03）。
- configs 段以精确全名排除两个日报运行时键；`pending_realm_settle:*` 与 `notify_daily_hour` 不受影响、照常往返（R2X-047）。

### 批次 9 · 删除接线 / 白名单 / RemoteAddr / 联邦离线

- 白名单刷新补接删转发（单删/批删）、批量换隧道、删用户与节点改址五路；relayTarget 出口集在隧道编辑时复检并在落库后重算 RemoteAddr、重下发（R2X-008/009）。
- 联邦隧道删除改离线容忍、编辑/重部署失败保留活隧道并转 pending 回滚语义；Force 断引用清单按引用 ID 去重并以「名称（节点名）」消歧；删节点回传跨节点引用清单、前端确认前点名（R2X-010/029/045，见 BC-R2-01）。

### 批次 10 · 通知台账与监控呈现

- 通知改通道级内存台账：任一通道成功后，同事件其他通道失败补发不再重复打已成功通道；恢复向三处补齐「成功才置位/重排」，日报使用不可变快照且成功后才推进（R2X-017/018）。
- 监控 access 数据补 Admin 标记，前端只读用户不渲染写入口与弹窗，四写入口 403 回归保持；监控信息栏改动态间隔文案（R2X-038/039）。

### 批次 11 · 前端回执与一致性

- 前端四处开始消费后端回执（failures/results/alreadyLatest/warnings），不再丢弃部分失败与警告；四函数补旧响应覆盖 seq 守卫（R2X-021/040）。
- 节点调优入口仅对非 nftables 模式显示；MutationPayload 类型层收口（补 groupIds/flowMiB、删幻影字段、submitData 去 any），发送键集合不变（R2X-041/042）。

### 批次 12 · 安装脚本

- install.sh 安装判活失败改返回非 0，自动化不再误判成功；回滚/启动分支在 `systemctl start` 前统一 `reset-failed`，避免 systemd 限速误判（R2X-019/020，见 BC-R2-04）。

### 补批 13/14 · 漏分配补关与夹具迁移

- tunnel/user 同名创建补提交段内复检（未加 uniqueIndex，按裁定以复检为止），确定性并发交错下不再双落（R2X-049）。
- 补批 14 仅迁移跨批冲突的测试夹具至真实网络口径，断言与生产代码零改动。

## 行为变更（逐条附可转发通知文案）

1. **BC-R2-01 联邦隧道删除改离线容忍**：联邦对端不可达时删库照常成功、残留清理转后台重试；编辑/重部署失败不再拆活隧道。
> 本版起，联邦对端离线时删除联邦隧道也会成功，残留清理会在对端恢复后由后台自动完成；编辑或重新部署失败时原隧道保持可用，不会被拆掉。
2. **BC-R2-02 分组停用真正收回授权**：停用分组开始撤销组建授权并清理其转发，重新启用按成员关系补发；存量停用分组在升级后首次状态变更/同步时追溯撤销。
> 本版起，停用分组会真正收回该分组发放的隧道授权并清理其转发，重新启用后按成员关系恢复；升级前已停用的分组，会在升级后第一次状态变更或同步时一并收回历史组建授权，手工单独授予的授权不受影响。
3. **BC-R2-03 备份恢复零倍率保真**：备份恢复后 TrafficRatio=0 的隧道保持零计费，不再被错误改回 1 倍。
> 本版起，备份恢复后计费倍率为 0 的隧道将保持零计费，不再被错误改回 1 倍；此前恢复过 0 倍率隧道的，请复核其倍率设置。
4. **BC-R2-04 install.sh 判活失败退出码**：install.sh 安装判活失败的退出码由 0 变非 0，屏显口径不变。
> 本版起，install.sh 安装后判活失败将以非 0 退出码结束；用脚本或自动化安装的请按退出码判断成败，不要只看屏幕输出。
5. **BC-R2-05 入站计数首采口径**：入站计数首采/epoch 变化不再把历史累计值计入，与订阅/转发管线统一。
> 本版起，入站流量计数在首次采样或计数代次变化时会先重建基线，不会把此前的历史累计值重复计入；正常连续采样不受影响。
6. **BC-R2-06 幂等并发回放**：同 Idempotency-Key 的并发第二请求由「执行并返回新结果」变为「回放首结果或 409 处理中」；不带键的调用方不变。
> 本版起，带同一 Idempotency-Key 并发重复提交时，第二个请求会回放第一次的结果或收到 409「处理中」，不会重复创建；不带该请求头的调用方式不变。
7. **BC-R2-07 sing-box 订阅 Snell 略过**：sing-box 订阅中 v1/2/3 与越界/缺失版本的导入 Snell 节点由「在但毒化整份」变为「略过」；Clash/Surge 行为不变。
> 本版起，版本不适用于 sing-box 的导入 Snell 节点不会再让整份 sing-box 订阅失效，而是只略过该节点；Clash 与 Surge 的输出不变。
8. **BC-R2-08 地址接受面收紧**：普通用户转发目标、导入主机、联邦目标与监控目标（allow_private 下）的非公网/元数据形态按统一分类器拒绝；管理员与既有例外开关不变。
> 本版起，转发目标、导入主机、联邦目标和监控目标的地址校验统一收紧：元数据、链路本地及内嵌同类地址会被拒绝；管理员操作与原有显式例外开关不变，存量条目再次编辑或探测时请使用合规地址。
9. **BC-R2-09 分配 ID 存在性**：分配类 API 传不存在的 ID 由静默成功变整体报错；前端正常路径无感。
> 本版起，分配订阅、分组或隧道时传入不存在的 ID 会整体报错，不再显示成功却没有实际分配；通过面板正常选择对象的操作不受影响。
10. **BC-R2-10 入站凭据留空保留**：更新入站时凭据子字段留空不再静默轮换（含 UUID/Password）；有意轮换走显式新值或 `/inbound/regenerate`。
> 本版起，编辑入站时把凭据子字段留空表示保持原值，不会再悄悄生成新凭据；确需轮换时请填写新值或使用重新生成入口。
11. **BC-R2-11 备份悬空附属引用剥离**：备份导入对悬空附属引用改剥离 + 警告回执，此前为静默保留悬空值；合法备份行为不变。
> 本版起，备份导入发现指向不存在对象的附属引用时会剥离该引用，并在导入回执中明确警告，不再静默保留无效值；合法完整的备份导入不受影响。
12. **BC-R2-12 订阅未知值过滤**：订阅保存时 Regions/Protocols 的未知值被过滤；正常前端数据不受影响。
> 本版起，保存订阅时 Regions 与 Protocols 中无法识别的值会被过滤，不再原样落库；通过面板正常选择的数据不受影响。
13. **BC-R2-13 备份 configs 日报键排除**：备份 configs 段不再包含 `notify_daily_last`、`notify_daily_inbound_total` 两个日报运行时键；其余配置键不变，`pending_realm_settle:*` 照常往返。
> 本版起，导出的备份不再包含两个日报运行时状态键，避免恢复到其他实例时带入旧的日报进度；其他配置与待结算状态的备份恢复不变。
14. **口径纠正（R2X-004，原 1.3.5 BC-13）**：1.3.5 发版说明 BC-13 的「面板 UI 无需任何操作」表述作废：1.3.6 起面板 UI 创建表单自动携带 Idempotency-Key，API 调用方口径不变。
> 更正说明：1.3.6 起面板 UI 的创建表单已自动使用 Idempotency-Key 防重复提交，无需用户额外设置；API 调用方是否携带该请求头仍由调用方自行决定。

## 升级注意事项

- **netguard 拒绝口径（BC-R2-08）**：硬拒层包括 loopback、未指定地址、169.254/16 整段、已知元数据字面量与 NAT64 内嵌同类地址，且硬拒先于 allowlist/allow_private 例外；一般私网地址仍按既有 `allow_private`/allowlist 开关与管理员口径处理。存量条目可继续存在的，不代表其在再次编辑保存、导入复检或拨号探测时还能通过新分类器，请按报错改成合规的公网地址、域名或已显式放行的私网目标。
- **BC-R2-02 追溯撤销**：存量已停用分组在升级后首次状态变更/同步时追溯撤销历史组建授权并清理其转发；只影响分组发放的授权，手工单独授予不动。若不希望触发追溯清理，请勿在升级后对存量停用组做无关状态切换，先核对成员与转发清单。
- **BC-R2-03 倍率复核**：此前经备份恢复过的 TrafficRatio=0 隧道可能已被旧版本错误改回 1 倍；本版只保证后续恢复保真，不自动改写现存倍率，升级后请复核这类隧道。
- **幂等前端接线（BC-R2-06 + 口径纠正）**：面板 UI 的 12 个创建表单已自动生成并复用会话级 Idempotency-Key，普通用户无需操作；双击、网络重试与并发同键提交可能回放首结果或收到 409「处理中」。API 调用方不带键时行为不变，带键时须保证同一业务请求复用同键、不同业务请求不用同键。
- **日报台账内存态口径**：通道级送达台账与日报待发状态为进程内存态。正常运行时按通道去重、失败只补未成功通道；若在「部分通道已送达、其余待补发」期间重启面板，待发快照会丢失并按最新累计值重算重发，已送达通道可能多收一份重算版日报（发版门项 7 已按此登记口径实测吻合）。`pending_realm_settle:*` 是独立的持久化待结算键，不属于日报内存台账，仍照常落库往返。
- **断言更新登记 #2 的认可说明**：批 9 的测试断言更新经 R2 交叉复核裁定驱动、单独提交 `397831c`：主项 `TestTunnelDeleteReportsRemoteFailureAndKeepsTunnel` 按 BC-R2-01 改写为离线删除容忍并删库的新语义；同提交 3 处连带调整均是同一裁定直接推翻的旧语义（pending/active 子句、联邦重试前补删库动作、Force 清单消歧元素等式），计数与元数据等其余断言未放宽。此项是对测试口径的正式认可说明，不构成额外产品行为变更。
- **check-contract-fields C7 口径**：C7 的 8 条红在未改动的 1.3.5 main 基线同命令复跑同样出现，属检查脚本与已发布代码的口径不一致、非 1.3.6 引入；本版未擅自改判或为过检改代码，已登记 R3 做「脚本更新或类型回迁」二选一裁定。
- **发版同步清单**：`skills/flmx-api/package.json`、`SKILL.md` 与 `doc/ai-skill.md` 的版本字面量已同步到 `1.3.6`（提交 `7f99cf0`，check-doc-consistency 三处一致 PASS）；发布副本的 `PINNED_VERSION` 由流水线改写，不手工编辑。
