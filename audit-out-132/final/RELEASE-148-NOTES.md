# FLMX 1.4.8 发版说明

- 基线：main @ 7244fbb（集成树 integrate-148b：四路集成 + connIdle 出口侧修复）；DOC 入站指南新增「空闲超时（秒）」一节。
- 变更面重审：新增产品 P0/P1/P2 = 0、P3 = 5，符合可发布标准（PORT-148-REA-UDIT.md）；发版门重验全 PASS（PORT-148B-GATE.md）。
- 兼容性：本版四项内容均为加法兼容，无破坏性变更——新字段留空时无行为变化、列表接口只多回字段、其余为展示层变化。逐项已核对，无 BC，见各节注记。

## 一、一键测算修复

> 「一键测算」现在会返回真实的测算结果了：延迟中位数是实测值，不再悄悄回落到默认值；测不到时也会明明白白告诉你这是回落值、为什么没测到。
>
> - 之前点完什么都不显示，是因为 agent 读错了内核数据的偏移，拿到的全是 0，被当成“没测到”丢掉了；另外部分内核拒绝旧的查询方式，现在按协议族分开查询。
> - 回落时建议值会明确标为“回落值，未采到实测中位数”并给出原因；建议值始终可以一键填入。
> - 探测绝不自动应用：采纳只填进输入框，下发仍须点「应用」。

技术注记：`tcpi_rtt` 偏移 72→68（72 读到的是方差 `rttvar`）；sock_diag dump 按 AF_INET + AF_INET6 分族发送；前端回落结果行展示。真机验证：两次探测一致，`rttSamples=8、中位数 11ms`，`ss -ti` 交叉印证。无 BC（展示层与 agent 内部取数路径）。

## 二、新增：入站空闲超时（秒）

> 入站创建/编辑表单新增「空闲超时（秒）」：该入站的连接空闲超过设定秒数后由节点主动断开。
>
> - 填 `1–86400` 的整数秒；留空表示不设置，走 Xray 默认 300 秒；显式填 `0` 会被拒绝。
> - 仅 Xray 内核可用；sing-box 内核没有 Xray 式空闲超时，字段禁用并会明示原因。
> - 不同入站可设不同值，互不干扰；删除入站后对应的超时配置一并撤下。
> - 已知行为（上游 Xray 侧，非面板缺陷）：VMess/SS 的完全静默会话约 1 秒即由上游机制收尾，先于设定的定时器；批量传输后的会话关断约为设定值的 2 倍（如设 5 秒约 10 秒关断），会话均会被回收。

技术注记：逐入站分 level 1..N（level 0 永不写，超 255 个带值入站渲染期 fail-closed）；Xray 会话的空闲定时器实际由出口侧 `userLevel` 决定（VLESS 入站无用户级定时器，系上游缺口），故每带超时入站渲染专用 freedom 出站 `flmx-idle-<id>`（`settings.userLevel`）+ 组合出站（level 与流量 mark 同在，不丢单用户计量），链式出站用户带 level；policy 段随配置文件原样落地 agent，无需 agent 侧改动。真机验证：主凭证与用户凭证均 5 秒上下关断，对照入站 15 秒不断。无 BC（新字段留空不下发 policy 段，存量入站行为不变）。

## 三、节点延迟显示断链修复

> 节点页的延迟区回来了：以前即使配好了测试点、等足时间，卡片和列表两视图的延迟也一直是空白——因为列表接口根本没把探测结果发给页面，手动重测的按钮又只在有结果时才出现，死锁了。这版把结果接进了列表接口，配好测试点、等一轮探测（约 3 分钟）后延迟就会显示；显式选了“不测延迟”的节点会显示「不测延迟」药丸。

技术注记：`nodeList` 在 `ListNodes` 返回后按节点贴 `latency`（仅有结果且 points 非空时）与 `latencyTargets`（仅显式自选时，无自选省略以保持“自定义”语义）。无 BC（列表只多回字段，前端渲染条件不变）。

## 四、节点页零测试点提示

> 还没配延迟测试点时，节点页的延迟槽位不再是一片空白：在线节点会显示「未配置测试点，去设置添加」，点一下直达设置页的「延迟测试点」卡。

技术注记：节点页挂载时只读一次池状态（复用设置页同一接口，不新增接口），仅管理员读取，读取失败不提示不误报。无 BC（纯展示层新增分支）。

## 已知问题（不阻塞）

- 148-P3-1：connIdle 越界错误文案称“0 不是合法值”，但 API 语义里 0 是合法的清除值，前后矛盾（仅文案）。
- 148-P3-2：存量非 Xray 入站若已带 connIdle 值（须库外写入才触发，常规路径到不了），编辑弹窗无清除路径（输入框禁用、编辑态内核选择器禁用），恢复须走直接 API 调 `connIdleSeconds: 0`。
- 148-P3-3：测算 RTT 腿失败时前端整单取回落值，丢弃测速腿已测到的带宽。
- 148-P3-4：`attachNodeLatency` 静默吞掉 targets 查询错误，无日志，排障时无法区分“无自选”与“查询失败”。
- 148-P3-5：单族 sock_diag 失败被无声吞掉，中位数可能只基于一个协议族且无 warning。
- REA-P3-1（沿袭）：Gist 自动循环在「令牌 + 间隔已设、密码被清」态下，每 5 分钟发一次失败通知（仅通知噪声）。常规 UI 路径不可达，直接 API 调用可达。
- O-148B-1：VMess/SS 完全静默会话约 1 秒即由上游机制收尾，先于面板 5 秒定时器；方向安全（更早关闭、不泄漏）。
- O-148B-2：批量传输后会话关断约为设定值的 2 倍，疑为 Xray 空闲计时粒度；会话均被回收。
