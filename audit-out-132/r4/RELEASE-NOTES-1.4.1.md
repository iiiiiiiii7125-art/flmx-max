# FLMX 1.4.1 发版说明

R4 全量审计修复补丁版：在 1.4.0 之上完成新一轮「基线（钉死 tag 1.3.7 口径、同型逐条核对 main 现行代码）→ 12 域并发审计 → 交叉复核裁定 → 9 修复批 + 文档批 → 补修 3 批 → 发版门两轮真机复验」循环，本版是该轮全部修复成果。用户已预授权按交叉复核推荐口径执行（含全部行为变更项）。

## 版本概览

- 审计总账（R4-X-ledger 去重合并后）：**P0 = 0 / P1 = 2 / P2 = 4 / P3 = 16，合计 22 条**，另裁定项 R4-SIP023-R（SIP023 多段解除）与条件立项 R4X-021。22 条中 20 条在修复轮关闭；R4X-021 按计划门先行、已由发版门三步验证结案；R4X-022 的 Fix2A 子项经 spike 定性为产品竞态、连同批 6 顺查坐实的 E4-S1 以补修批关闭（占位编号 R4X-023 / R4X-024，台账追认留 R5）。发版门首轮唯一 FAIL 的 F-S01（PG 计数并发双计，R3 疑似升 P3 立案）已定点修复并复验通过。**计关闭：22 条 + SIP023-R + 补修 3 条（R4X-023、R4X-024、F-S01）**。
- 修复集成：`integrate-r4 @ 4167781`，自 main `a5a418f`（1.4.0 发布态）切出共 39 个提交（10 批合并零冲突 + 补修 3 批）；合入 main 零丢提交。
- 全量回归：go-backend / go-gost / go-gost/x 的 build/vet/test 通过（两处红已定性非本轮引入：沙箱 fake-IP DNS 的 health 单格环境红、R3 期既存的 PendingDelete 时序 flake，均有 pristine main 同签名复现证据）；前端 build 通过；check-contract-fields 全 PASS；check-doc-consistency 仅余 1 项既存 FAIL（技能包未覆盖 1.4.0 新路由 `/api/v1/node/traffic/month`，属移植线既存项、本版不扩面处理，登记 R5）。
- 发版门真机复验两轮：首轮 12 项 **11 PASS / 1 FAIL**（项 11 F-S01 PG 双计坐实）；定点修复（批 S3）后复验项 11 **PASS**（PG 契约两条 ×2 轮 + 逐字探针并发/顺序各 1 组），升级前后存量计数逐项一致，**放行发版**。两项裁决性验证同轮落定：R4X-021 以 rig 产物结案、SIP023 解除经 EIH 真实握手实证生效不回退。
- 行为变更共 7 条单列于下方 BC 节（BC-R4-01…07），每条附一行可直接转发的通知文案。

## 修复内容（按批次）

### 批 1 · 导入凭据校验收口（两条 P1）

- **P1（R4X-001）**：SS2022 cipher 大小写变体（如大写 cipher 名）此前可绕过校验原样落库、渲染时毒化整份订阅。本版在导入校验入口落库规范化为小写、渲染面对存量做小写化自愈、密钥长度真源谓词大小写不敏感化。关闭证据含 sing-box 1.14.3 与 mihomo v1.19.33 双二进制实测：自愈后双 exit 0、毒化复刻均 exit 1。
- **P1（R4X-002）**：Reality 公钥 / short-id 此前零校验，坏值落库后渲染毒化整份订阅。本版新增横切校验（含 reality-opts 即查，Trojan 同查，三条导入路径 + 通用 TLS 块）：公钥须 RawURL 可解码且恰 32 字节；short-id 非空时须为小写 hex、偶数长度、≤16 字符，空值放行。
- 自建面 SS2022 校验改调共享四形态解码核并限定单段（多段仍拒），与导入面同口径（R4X-013）。

### 批 2 · SIP023 多段解除（裁定项 R4-SIP023-R）

- 合法 SIP023 多段 SS2022 节点在 sing-box 订阅面由「整段略过」改为**逐段校验 + 逐段归一后下发**（真源谓词 `ValidSS2022SingleKey` 零改动，禁原样直出、禁一刀切放宽）；坏段仍按略过口径并单列。`doc/guide/import.md` 同批改版。旧版补测：sing-box 1.11.15 / 1.12.20 / 1.14.3 多段 `check` 与整份渲染均 exit 0。生效前提（发版门 EIH 真实握手）已过：客户端用订阅渲染的完整多段口令经 sing-box 实际代理取回标记、错误第二段被拒——**随本版生效、不回退**。

### 批 3 · 零值语义与 presence 收口

- **P2（R4X-004）**：tunnelUpdate 旧值改走原始读取（新增 `GetTunnelRecordRaw`，归一化版降为只读包装并注明禁止作写回源）——存量 0 倍率隧道编辑其他字段时不再被归一化改回 1，倍率 2.5 等正常值不回退。
- 0 倍率创建 / UI / 展示三面统一：可创建、表单放行 0、列表显 `0x`（R4X-010）。与批 3 的 R3 修复（计费消费层保留 0）合拢后，**零计费口径在创建、编辑、展示、计费四面全链兑现**。
- 入站部分更新补齐其余 8 键 presence 化：省略的可选字段保留原值（R4X-018）；限速规则部分更新接 presence 语义，缺席字段回填旧值、停用规则不被静默启用（R4X-019）；分组创建/更新补 status 枚举 {0,1} 与空名校验，撤销谓词由 `==0` 改 `!=1`（R4X-012）。

### 批 4 · 授权撤销与导入段收口

- **P2（R4X-005）**：撤销双组共享授权（cb=1 grant）时向剩余 grant 提升来源标志，防撤销后来源标记丢失导致后续误判；双序探针（正/逆序撤销）验证。
- **P2（R4X-006）**：备份部分导入的授权收口落 repo 事务尾：无对应授权的 userTunnels / forwards 行不再落库，改为 skipped 并在导入回执计数披露；全量恢复逐行对账零跳行（段序约束写死：forwards 先于 userTunnels，段内即时校验会误伤同批全量恢复，故收口在事务尾）。

### 批 5 · 部分导入物化 reconcile（R4X-009）

- 物化后 reconcile 尾钩子触发条件放宽至任一物化输入集段（含 relays 子段），部分导入不再漏触发；全集 16 顶层段逐段定口径，三段探针验证全量恰一轮。

### 批 6 · 回滚收尾补刷（R4X-003 / R4X-011）

- **P2（R4X-003）**：切隧道失败回滚的两条返回路径各按收集集补刷白名单一次（三形态失败注入探针先红后绿 5/5）。单条 assign/update 路径 DB 回滚后按回滚后状态补 `syncUserTunnelForwards`，作用域仅本条转发集、失败不覆写原回执（R4X-011）。

### 批 7 · 同步守卫与服务监控硬拒（R4X-007 / R4X-008 / R4X-020）

- 订阅源同步的入站中转列表读取错误改 fail-closed（原 fail-open 会把真实错误当空列表继续同步）；同批完成 12 点 fail-open 普查（仅主守卫与去重门两点、均已关闭）。
- 服务监控目标接入硬拒子集：面板保存面与 agent 执行端同谓词——命中元数据/保留段等硬拒集的目标创建/更新被拒、存量坏目标在检查时跳过、拨号/发包前逐 IP 复检；内网、回环、CGNAT、fe80 等目标不受影响（LAN 四面回归全绿）。

### 批 8 · 通知指纹与回执透出（R4X-014 / R4X-017）

### 批 9 · demo 适配与联邦 deflake（R4X-015 / R4X-016 / R4X-022）

### 补修批 · S1 / S2 / S3

- **R4X-023（Fix2A 产品竞态，P3）**：`ensureRealmKernel` 的 check-then-insert 被 WS 异步上线与同步切引擎两条产品路径并发到达时报唯一约束冲突。收口于共用 repo 层 `CreateNodeKernel`：`ON CONFLICT DO NOTHING` 单语句插入 + 未插入回读既有行幂等成功，回读胜者行补版本收敛；同型面（kernelInstall）经同一收口点覆盖。原 flaky 用例 -count=10 10/10 PASS（用例一行未动）。
- **R4X-024（E4-S1，P3）**：删联邦共享时 Share-* 隧道与 relay 转发被裸级联删除、落地白名单残留已删隧道入口。`cleanupFederationTunnels` 补删前收集受影响入站集 + 删后统一刷新白名单（与 tunnelDelete 同一 funnel）；删除级联语义零改动。
- **F-S01（PG 计数双计，P3，发版门首轮 FAIL 项）**：PG 部署下入站/订阅计数管线「读基线 → 算 delta → 累加」在并发重叠调用（定时轮与重启/切引擎/重连）时同读旧基线双计（门上实测订阅恰 2×、入站多路重复；SQLite 因连接池串行不受影响）。两条管线的基线读改 `SELECT … FOR UPDATE` + 确定性锁序，delta 语义零改动、SQLite 行为逐字不变。新增 PG 契约两条（双管线并发同一样本只入账一次）随 CI 实跑，发版门复验两轮 PASS。

## 行为变更（BC-R4-01…07）与可转发文案

1. **BC-R4-01 · 导入凭据校验扩大**（R4X-001/002）：导入节点的 SS2022 cipher 大小写变体落库时规范化为小写；Reality 公钥 / short-id 不合法的节点逐条拒绝导入（既有坏存量按渲染略过口径，不毒化整份订阅）。
   > 📢 升级通知：新版加强了导入节点的凭据校验。Reality 公钥或 short-id 填写不合法的节点将无法导入，请按规范格式填写；已导入的异常节点会在订阅中被自动跳过，不影响其他节点使用。
2. **BC-R4-02 · 0 倍率四面统一**（R4X-004/010）：倍率 0 的隧道可创建、可编辑、显示 `0x`、部分更新不再被改回 1，零计费口径在创建/编辑/展示/计费全链兑现。
   > 📢 升级通知：倍率为 0 的隧道现在全程保持 0 倍率（免费），编辑隧道其他设置也不会再把倍率悄悄改回 1 倍。
3. **BC-R4-03 · 入站部分更新 presence 化**（R4X-018）：API 部分更新入站时，省略的可选字段改为保留原值；需要清空/关闭请显式传空值 / false / 0。
   > 📢 升级通知：通过 API 更新入站时，只传要改的字段即可，其余字段保持原值；要清空某项请显式传空值。
4. **BC-R4-04 · 限速与分组校验**（R4X-019/012）：限速规则部分更新同 presence 口径；分组 status 只接受 0/1，非法值直接拒绝。
   > 📢 升级通知：分组状态只接受 0（停用）/ 1（启用），传其他值会被拒绝；限速规则只改一项时其余设置保持不变。
5. **BC-R4-05 · 备份部分导入授权收口**（R4X-006）：备份部分导入时，无对应授权的 userTunnels / forwards 行不再落库，改为 skipped 并在导入回执中计数披露。
   > 📢 升级通知：部分导入备份时，没有对应授权的转发记录会被跳过并在导入结果中计数提示，全量恢复不受影响。
6. **BC-R4-06 · SIP023 多段 sing-box 下发**（R4-SIP023-R）：合法 SIP023 多段 SS2022 节点在 sing-box 订阅由「略过」改为逐段规范化后下发（已以 sing-box 1.11 / 1.12 / 1.14 实测兼容）；其余客户端面口径不变。
   > 📢 升级通知：多段密钥的 SS2022 节点现在可以正常出现在 sing-box 订阅里了（此前会被跳过）；建议 sing-box 客户端保持在较新版本。
7. **BC-R4-07 · 服务监控硬拒集**（R4X-008）：服务监控目标命中硬拒集（云元数据地址、保留段等）时创建/更新被拒；内网与回环目标不受影响。
   > 📢 升级通知：服务监控不能再以云元数据地址等特殊地址为目标（会被拒绝）；内网和本机目标照常可用。
