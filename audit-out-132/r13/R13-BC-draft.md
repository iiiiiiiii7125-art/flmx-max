## BC-R13-01：恢复后在线节点转发数据面重推（R-a / R13X-001，P2）

- 来源：批 R 断言 R-a，R13X-001（备份导入后在线节点转发数据面无重推触发、回执报成功）。
- 行为变化：备份恢复后，在线节点的转发数据面改为与正常写路径一致重推
（gost 服务 / nft 规则 / 已存中转 RemoteAddr 重算）；离线节点重连补推路径行为不变。
- 用户操作：**无**。无需手工再编辑转发、无需重连节点。
- 迁移：**无**。无 DB schema 变更，无 agent 协议变更。
- 注意事项（注记中必须写明）：重推可能致在线服务短暂重建——恢复后在线节点的
转发服务可能短暂重建/替换（同 id 改参、改端口的旧服务被替换，不再按旧参数服役），
属恢复后的一次性重推行为，不是故障；回执中披露重推结果（至少失败节点清单），失败不静默。

### 可转发文案（BC-R13-01）

> 备份恢复后，在线节点的转发数据面现在会与正常写路径一致自动重推：
> 恢复出的转发服务、nft 规则与中转地址将按备份内容重新下发，无需您手工再编辑或重连节点。
> 注意：重推过程中在线服务可能短暂重建，属一次性恢复行为；若个别节点重推失败，
> 恢复回执中会列出失败节点，不会再静默报成功。无迁移、无需您额外操作。

## BC-R13-02：未知类型由静默成功改为报错（R-c / R13X-005，P3）

- 来源：批 R 断言 R-c，R13X-005（ExportPartial / Import 对未知类型字符串静默忽略）。
- 行为变化：导出（ExportPartial）与导入（Import）双侧对未知类型字符串**即报错**，
文案点名未知值；定版口径为报错而非仅 warnings——warnings 仍属「成功」语义，
改不掉误认已备份/已恢复的后果。
- 影响面：现行前端 16 值清单与后端集合逐值一致，故 UI 路径当前被掩盖；
本条主要影响**直接调用 API 的调用方**（拼错类型的部分导出此前产出「成功但缺段」的备份，
拼错类型的导入此前报成功但零恢复）。
- 直接调用方须做：若依赖旧的静默成功语义，须修正类型清单，剔除未知类型字符串；
合法类型清单行为不变。
- 迁移：**无**。无 DB schema 变更，无需数据迁移。

### 可转发文案（BC-R13-02）

> 备份导出/导入时，未知类型现在会直接报错并点名未知值，
> 不再静默成功。面板内正常操作不受影响（面板类型清单与后端一致）；
> 若您直接调用 API 且类型清单中含有拼错或未知的类型，请先修正清单，
> 否则调用将返回报错。无迁移。

## 其余条目无 BC 的理由登记（按 FIX-PLAN §5 定版口径）

除 BC-R13-01/02 外，R13 修复批其余五条均不立 BC，理由如下：

| 条目 | 断言 | 无 BC 理由 |
|---|---|---|
| R13X-002（P3） | T2-a：`tunnelCreate` 的 `type`/`status` 守卫补齐 | 守卫类 fail-closed 收口：仅把非法输入挡在库外，合法建库行为不变 |
| R13X-003（P3） | T2-b：面板编辑表单按 presence 口径省略 flow/trafficRatio | 内部口径对齐：面板请求形态与后端保证前提对齐，存量值原样保留，无用户可见契约变更 |
| R13X-004（P3） | R-b：inbounds 子段导入计数 | 计数类加法字段：回执新增与既有 `*Imported` 同形的计数字段，旧客户端忽略新增字段 |
| R13X-006（P3） | R-d：导入型行 Protocol 以 `ProxyProtocol(Extra)` 重推导 | 派生字段修正：Protocol 本就是派生字段，重推导与创建/编辑路径同口径，备份原值仍在 Extra 内完整保留 |
| R13X-007（P3） | T2-c：恢复面复用保存面两门（`validateTunnelFlow` ∈ {1,2}、`validateTunnelTrafficRatio` ∈ [0,100]，域外行跳过 + 点名） | 恢复面门与保存面门对齐的 fail-closed 收口：与 forwards status 门同形，属同一校验口径向恢复入口的补齐，不立独立 BC |

- 附注：R12X-002 重定本身亦不产生 BC——它是历史定级修正（见
`R13-R12X002-redetermination-draft.md`），产品修复已在 R12 批 X 落地，无新增行为变更。
