# FLMX 1.3.4 发版说明

全量审计修复版：1.3.2 发布后按用户任务书完成一轮「基线 → 13 路静态 + 真机 → 交叉复审 → 深挖 → 分批修复 → 对抗复审 → 再修复」的全量循环审计，本版是该轮的全部修复成果。

## 版本概览

- 审计总账（SUMMARY-DEEP 合并 DECISIONS-132 与深挖轮）：**P0 = 0 / P1 = 8 / P2 = 55 / P3 ≈ 88+**，另有疑似 9 条逐条定案；
- 修复轮九路（FIX-A…I，37 提交）+ 对抗复审六路（V1–V6）主体全关闭，复审新发现的 **P2 × 3 与 P3 一批**已在第二修复小循环（FIX2-A/B/C，17 提交）全部关闭；
- 集成树全量验证：后端 15/15 包、go-gost/x 27 包、前端 tsc 0 错误、敏感键与文档一致性脚本双 PASS；
- 行为变更共 9 条单列于下节，每条附一行可直接转发的通知文案；无破坏性数据迁移，存量订阅链接、备份格式保持兼容。
- 与紧急版 1.3.3 的关系：1.3.3 是仅含浏览器死缓存修复的紧急版（PWA Service Worker 改 autoUpdate 立即接管 + 出站面缓存口径统一）；本版 1.3.4 包含同一缓存修复（超集），从 1.3.3 升级不回退该修复。

## 修复内容（按域）

### 安全与日志脱敏

- WS 握手凭据不再随 query 落进 nginx access_log（`/system-info` 等位置关日志）；全仓日志点统一脱敏：secret / token / 密码类值与带凭据 URL 一律掩码，`*url.Error` 内嵌的完整 URL 同步清洗；
- 第三方订阅源 URL 的 path 型 token（如机场订阅链接）不再原样落进 fetch 日志；agent 侧脱敏改 fail-closed（解析失败回占位符，不回退原文），参数名大小写不敏感、同名参数全掩；
- 命令日志的脱敏渲染改真 JSON 解析后按键掩码，堵转义引号绕过；
- GitHub 镜像代理限流桶加过期清理与上限淘汰，长跑后新 IP 不再被永久拒绝。

### 鉴权与会话

- 「仍用默认密码」标志在密码登录、JWT、passkey 三条路径统一按库存值判定（修复密码登录路径漏判的修A漏B）；
- 订阅存储用户名枚举的时序差消除（不存在用户分支补等时 bcrypt）；
- WS 广播改白名单（仅 metric / upgrade_progress）+ 每会话异步队列，慢消费者不再队头阻塞全站；WS 升级加未认证限流与 per-user 连接上限；删除节点时踢掉其 WS 会话并周期复验绑定。

### 转发与计费

- **P1**：日/月配额执法补齐 nftables 分支——nft 转发超额现在真正暂停（见行为变更）；暂停改为增量执法，首轮下发失败/节点离线不再永久跳过，恢复后自动补暂停（FIX2）；
- 引擎切换（gost ↔ realm）边界补双向结算：切换前拉一次计数落账，迟到入账消除；离线切换记 pending 标记，重连后先结算再下发；
- realm 多目标与 fifo/least 策略改明确拒绝（见行为变更）；create 与批量创建补齐 warnings 回执；换隧道 nft 清理补全，切换失败向上抛错不再静默；
- nft 规则按 BindIP 收紧匹配，RuleHash 纳入 BindIP 防误判漂移重复计数；
- 三个 update 接口改真部分更新：未传字段一律不动（修复未传 forwardMode 把 nft 节点翻回 agent 模式等整族问题）；嵌套 `sshConfig` 同口径下钻，漏带时不再把非 22 的 SSH 端口改回 22（FIX2）；在场但不可解析的值改为明确报错、不再硬套默认值；
- 转发计数入账加 per-node 串行化，settle 与周期轮询并发同一样本不再双计；入站计数单事务按 200 条分片，消除每 60 秒占满唯一 DB 连接的周期毛刺；
- 订阅与转发的计数 epoch 口径统一：epoch 变化视同基线重建（见行为变更）。

### 数据、备份与迁移

- **P1**：nftables SSH 校验移出 DB 事务与端口锁（原最长 15s × 入口数独占唯一连接，现每请求只校验一次）；
- 级联删除统一物化 relay id 集合，删节点/隧道/内核不再误删其他节点的授权、不留孤儿；
- 备份族整体对齐订阅段标杆：全段引用重映射 + 存在性校验 + 唯一冲突占位预处理 + 跳过回执，不再出现「悬空引用回执成功」「一条冲突整单回滚」；
- 备份字段保真补完：配额的 PausedForwardIDs 与已用量往返保真（恢复后被暂停的转发能正常自动解封）、订阅计数器恢复改为「缺失只建基线」（消除恢复后重复计数）、节点 SSH 配置与联邦共享定义进备份、联邦 relay 凭据列进备份（且旧备份重导入不会清空现存凭据）、内核 InstalledVersion、订阅源 Userinfo、待删订阅语义、导入用户不再删配额行；
- 停用的联邦共享与绑定在恢复时保持停用，不再被 `default:1` 复活（FIX2）；
- **P1**：SQLite → PostgreSQL 官方迁移打通——`release_legacy_family` 一列的默认值翻译不再让 pgloader 建表 FATAL，模型与脚本双侧修复（脚本侧预处理只改该段、原库不动）；
- PG/SQLite 双言迁移顺序修复：重复 chain_tunnel 与重复 TunnelMetric 样本先去重再建唯一索引，不再让存量库启动死在建索引；
- 备份导入后失效通知与探测配置缓存，导入的配置立即生效。

### 通知与监控

- 零值标志家族收口：公告、服务监控、内核等 5 处 `Enabled` 类字段在创建与备份恢复双路径都不再被默认值吞成启用；
- 延迟测试点配置校验正式接线（五种坏值在创建/更新双路径报错不落库）；
- 告警语义修正：恢复送达后清除指纹，同一问题恢复后再发作会重新告警（不再被永久吞掉）；改为发送成功才置位 + inflight 占位，多通道部分坏死时只重试失败通道、并发同指纹只发一次；
- 隧道质量探测降载：单轮查询 15 → 8、整轮批量 + 配置缓存，20 条隧道稳态不再以 30–80 qps 砸单连接 SQLite；内核状态轮询改并发（上限 8），单个假在线节点不再拖住整轮；通知发送改有界队列 + worker，不再无界开 goroutine。

### 前端

- 全量替换守卫整族：订阅分配页、用户分组、公告编辑三处在加载失败时不再把空集保存成全量清零（统一 loadError 守卫），其余 9 个同类表单逐个复核无同病；
- 备份导出假成功修复：以 `Content-Disposition: attachment` 为成功判据，后端错误信封不再被存成「备份文件」还报成功；
- 备份导入加确认框（写明覆盖语义与导入前自动备份兜底），全产品唯一的无确认覆盖操作补齐；
- 前后端敏感键名单对齐（11 键）并新增一致性检查脚本防再次漂移；监控页 403 改 api 层统一静默；公告双渲染管线统一组件并补 sanitize；隧道删除确认加离线语义注记；引擎文案纠正。

### 订阅与导入

- NodeCount 改为与实际渲染完全同流水线：列表显示数与各格式真实拉取数一致（四格式与真机实得 8/9/8/7 逐一对齐）；「我的订阅」计数再按用户分配过滤，与个性化链接实际拉到的数量恒等（FIX2）；format 参数大小写口径两入口统一；
- 流量统计时区聚合改 IANA 分桶：跨时区/夏令时的小时数据按分钟比例拆分、总量精确守恒，UTC+8 口径与旧版逐字节一致；
- sing-box 配置回导补 Snell / Naïve 映射与防毒化；Clash 导入改逐条容错（坏条目只丢并回执，不再整份拒绝或静默吞）；解析器静默降级族收口：小数端口截断、vmess aid 溢出、tls 块错位一律明确拒绝并回执。

### 部署与脚本

- `update_panel` 改版本感知防降级（含不可比版本放行口径），并交叉核对后端容器实际运行的镜像版本：与 `.env` 记录不一致时告警并以实际版本判定，防 `.env` 被手改绕过（FIX2）；
- PG 迁移脚本：停服前口令校验（空/默认自动生成并写回.env）、`.env` 快照 + 健康检查失败自动回滚；
- 前端 healthcheck 改 127.0.0.1；nginx 落 F-5 安全头；compose 模板子网改 172.30.0.0/16（仅新装，见升级注意事项）；compareVersions 严格化为 `(int, error)`，五处调用点全部改 fail-closed；
- 文档批：新增监控 guide、术语交叉引用、数字口径补齐与四处勘误、mihomo 1.19.15 的 Snell 注记、离线删隧道语义入文档。

### agent（节点）

- **P1**：面板内升级不再硬编码 systemd——init 抽象与 install.sh 对齐（systemd / OpenRC / 无管理器明确报错），Alpine 节点可正常面板内升级；
- **P1**：升级安全链补齐：替换前 `-V` 冒烟（10s）、备份写失败即中止、重启脚本本地健康检查 + 自动回滚（不依赖 WS 连通），结果落 `agent-upgrade.log`；
- SS / chain fail-closed（见行为变更）；WS 命令面禁自动降级 + 信封时间戳 ±5 分钟窗（见行为变更）；HTTP 上报同口径禁降级（FIX2，见行为变更）；
- 命令 gzip 解压上限 10MB、checksum 读取上限、服务监控超时钳制 [5,60]s、createServices 落盘失败还原快照；
- 链路错误带链名（ErrEmptyRoute 包装），面板与日志可定位是哪条链断；
- 面板生成节点安装命令时自动补显式 scheme（FIX2），新装节点不再落裸地址坑；前端 nginx 的 X-Forwarded-Proto 改透传上游值，Caddy 部署下 scheme 推断不再恒错。

### 联邦（面板共享）

- **P1**：middle/exit 角色服务恒带每共享独立的 relay 凭据（创建生成 / 启动回填存量 / 懒补发 / 同步自愈四路齐），开放中继关闭；middle 目标加私网校验，share 加载失败整单失败不降级；
- **P1**：runtime/command 服务配置加类型白名单（面板构建全集反查对表），file / sshd / tun 等危险类型一律拒绝下发；存量已落库的期望状态在启动时补一遍白名单复检，危险存量置 paused 并告警（FIX2）；
- exit 侧连接时私网过滤经 agent 内置 bypass `flmx-no-private` 落地：面板按 agent 版本门（≥ 1.3.4）下发，旧 agent 不下发、无 fail-open 假象（FIX2）；
- PeerShareRuntime 改复合唯一 (share_id, resource_key)：多消费方同键不再互相撞键拒绝；端口范围 0/0 三条路径统一 fail-closed；
- 出站联邦客户端 SSRF 硬化：pinned-dial transport 逐跳复检（上限 5 跳）、跨主机剥凭据头、拨已校验 IP、云元数据地址恒拒、私网放行走显式 allowlist；`nodeCreate` 直填 remoteUrl 与导入路径共用同一校验实现；
- peer 端点错误回吐脱敏；diagnose 的目标 IP 改面板解析后钉死下发，消除 DNS TOCTOU；
- Connect 双向携带 panelVersion，低版本对端有回执警告与日志（见行为变更的升级顺序）。

## 行为变更（逐条附可转发通知文案）

1. **无密码 SS 配置报错**：无 auth（或 method/password 任一为空）的 SS/SSU/TAP 配置（导入的 gost 配置、手工链、手工配置）组件直接报错、服务起不来，不再静默以明文运行。面板正常创建的 SS 入站与 SS 链恒带密码，不受影响。
> 本版起，无密码的 Shadowsocks 类配置（导入/手工 gost 配置）将直接报错、不再以明文运行，请为这类配置补上密码；面板正常创建的 SS 入站与链不受影响。
2. **chain 故障明确断开**：多跳链任一跳全部节点不可用时，连接明确失败（带链名报错），不再静默截断绕行、更不再在首跳故障时静默变成本机直连出站。链健康时行为不变。
> 本版起，多跳链中任一跳全部不可用时连接将明确失败，不再静默绕过该跳或改走本机直连；链健康时无变化。
3. **节点 addr 裸地址迁移（WS 命令面）**：agent 只按单一 scheme 连接，不再 wss 失败自动回退 ws；裸地址默认 wss。无 TLS 面板 + 节点 config 写裸地址的存量节点，agent 重启后连不上（日志有明确政策说明）。新装节点已由面板自动补显式 scheme，不受影响。
> 无 TLS 的面板、且节点 config 里 addr 为裸地址（无 ws:// 前缀）的部署，升级后请把节点 config.json 的 addr 改为显式 ws://<面板地址>（或给面板部署 TLS），否则 agent 重启后连不上；新装节点不受影响。
4. **HTTP 上报同口径禁降级**：流量/配置上报的候选地址与命令面同口径收敛为单一 scheme（裸地址默认 https，显式 http:// 即确认明文），删除 https→http 自动回退。上报体本为 AES 密文，但 secret 以 query 明文随行，故同批处理；迁移方法与上一条同一条。
> 明文部署的节点请把 config.json 的 addr 写成显式 http:// 前缀：本版起流量上报与命令面同口径，不再自动降级到明文，裸地址将只尝试加密连接。
5. **联邦升级顺序：先消费方、后提供方**：提供方 role 服务恒带凭据后，旧消费方连新提供方会被拒（控制面全成功、数据面不通的静默断裂）。先升消费方则全程零断裂；Connect 已携带 panelVersion，低版本对端会在回执出现 versionWarning 并记日志。（注：此顺序与审计修复初版的推荐相反，以对抗复审 V5 的四格矩阵推导为准。）
> 使用面板共享（联邦）的双方请按「先消费方、后提供方」的顺序升级到 1.3.4；反序升级会让旧消费方的中转链在提供方升级后暂时不通（面板显示正常、流量被拒），消费方升完即恢复。
6. **realm 不支持的策略明确拒绝**：realm 隧道的多目标与 fifo/least 策略在创建/更新时明确报错拒绝，不再静默落库成无效配置；单目标默认策略不受影响。
> 本版起，realm 隧道的多目标与 fifo/least 策略将在创建/更新时被明确拒绝（realm 本身不支持），单目标隧道不受影响。
7. **NodeCount 口径**：订阅节点数改为按目标格式实际可拉取的数量统计，「我的订阅」再按用户分配过滤——显示数字可能与旧版不同（旧版是声称值），以实际拉取为准。
> 订阅列表显示的节点数改为按格式实际能拉到的数量计算（「我的订阅」按你的分配计算），数字可能与旧版不同，以实际拉取到的为准。
8. **配额暂停真生效**：nftables 模式下日/月配额超额此前只扣费不暂停（执法无 nft 分支），本版起真正暂停；暂停在下发成功后才置位，首轮失败会自动重试补暂停。
> 本版起，nftables 模式下转发流量超过日/月配额会真正暂停（此前只扣费不暂停），配额恢复后自动解封。
9. **订阅计数 epoch 口径**：计数器 epoch 变化（节点重装、计数重置等）时改为重建基线，不再把累计跳变全量计入用量，避免用户用量一次性虚增；同 epoch 内的计数回退口径不变。
> 本版起，节点计数器重置（epoch 变化）时订阅流量改为重建基线，不会把重置前的累计量一次性计入你的用量。

另有两条同批口径（不单发文案，并入文档）：节点/面板时钟偏差超过 5 分钟时加密命令会被拒（先校时/NTP）；部分更新接口对「传了但不可解析」的值改为报错，不再静默套默认值或清空（如 expiryTime）。

## 升级注意事项

- **子网保留**：compose 模板子网改为 172.30.0.0/16 **仅对全新安装生效**；脚本更新与面板内升级两条路径都会把存量 compose 的子网与网络名保留进新文件，存量部署升级不会重建容器网络、容器 IP 不变。切勿手工把在用子网改成模板值。
- **裸地址节点先行处理**：无 TLS 面板 + 裸 addr 的节点，建议升级 agent 前先按行为变更第 3/4 条把 addr 改成显式 scheme，或随后按节点日志提示处理；新装节点无此问题。
- **联邦先升消费方**：见行为变更第 5 条；版本过旧提示（versionWarning）出现即表示对端未升到凭据感知版本。
- **dev（自构建）版本口径**：联邦版本提示对 dev 构建显式豁免（不误报警告）；exit 私网过滤 bypass 对 dev agent 按「不支持」处理、不下发（fail-closed）。自构建用户如需 exit 私网过滤，请使用正式版本号构建。
- **时钟**：节点与面板时钟偏差 > 5 分钟的老部署先校时再升 agent。
- **发版同步清单（发版动作时执行一条）**：`skills/flmx-api/package.json` 与 `SKILL.md` 的版本字面量随本版同步到 `1.3.4`（仓库内已在改号提交中同步为 1.3.4，check-doc-consistency 的三处一致检查随之更新）；发布副本的 `PINNED_VERSION` 由流水线按惯例改写，不手工编辑。
