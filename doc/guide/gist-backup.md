# Gist 备份

把面板的全量备份加密后上传到你个人 GitHub 账号的私密 Gist，并可按需定时自动上传。适用于异地留底、换机恢复；它不替代本地下载备份——Gist 侧的版本历史、访问权限与删除都由 GitHub 账号侧控制。

> 适用版本：随 1.4.6 引入。入口仅管理员可见；非管理员打开该区域不显示内容。
> 来源说明：功能原型与部分措辞（如私密 Gist、令牌权限要求）同源自上游 flyx 3.3.42 的 Gist 备份文档；品牌、加密口径、恢复段集合与自动上传默认值按 FLMX 口径重写，见下文。

操作路径：**网站配置 → 数据备份与恢复 → Gist 备份**（位于本地导入区下方）。

## 准备：个人账号的 classic token

- 用**你个人 GitHub 账号**持有令牌（T-1 口径：不要求组织或机器人账号）。
- 创建路径：GitHub 头像菜单 → **Settings** → **Developer settings** → **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**；**Note** 填用途名（如 `flmx-gist-backup`），**Expiration** 建议设一个期限、到期前回这里重新生成并更新到面板；权限只勾 **`gist`** 一项。生成的令牌只显示一次，立即复制。自检：回到 **Tokens (classic)** 列表能看到这枚令牌、且权限只有 `gist`，即创建正确。
- 创建 classic personal access token，勾选 **`gist` 权限**（读写 Gist）。令牌权限过大时面板实际只会用它调五类 GitHub 请求：保存时校验、创建 Gist、更新同一 Gist、版本列表、版本内容；但仍建议只给 `gist`，不要顺手勾上 `repo` 等无关权限。
- 保存设置时，面板会先向 GitHub 发一次 `GET /gists?per_page=1` 校验令牌可用，校验不通过不落库。请注意：这一步只校验“能调通 Gist 接口”，**不校验令牌是否恰好只有 `gist` 权限**，权限收敛靠创建令牌时自己把关。
- 面板服务器需要能访问 `api.github.com`（默认基地址；可用环境变量改写，见[高级](#高级-api-基地址)）。连不上 GitHub 时上传失败，失败信息写进状态里的 `lastError`，不会静默丢掉。

## 加密：必填，丢密码不可恢复

- **必须设置加密密码才能上传（T-4 口径：明文上传不放行）。** 留空密码时上传一律会被拒绝；保存侧只在**开启自动上传（间隔 > 0）且已填令牌**时才拒绝留空密码——间隔为 0（关闭）或未填令牌时，留空密码保存会被放行，之后手动上传时才被拒绝。这比上游“留空即明文上传 + 警告”的口径更严，原因是 FLMX 的全量备份除节点密码、订阅凭据外，还含节点 SSH 配置与面板共享定义，明文外发的敏感面更大。
- 加密方式：scrypt（N=32768、r=8、p=1）派生 32 字节密钥，AES-256-GCM 加密整份备份 JSON；信封带随机 salt（16 字节）与 nonce（12 字节）。改密码后下一次上传的内容哈希会变化，会产生一个新版本（见[未变化跳过](#上传规则)）。
- **密码只存在面板配置里（与令牌同级），不进备份文件、不下发给前端。丢了上传时的密码，Gist 上的加密备份永久不可恢复**——面板没有找回途径，换密码只能从新备份重新上传。
- 状态里的 `encrypted` 只表示“当前已设置加密密码”，`tokenHint` 只露令牌首 4 位与末 4 位（过短令牌全掩）。即使管理员经配置读接口（`config/list`、`config/get`）查看，也拿不到 `gist_token` / `gist_password` 明文；Gist 的 8 个配置键（见[配置键](#配置键)）全部不进本地备份文件，恢复旧备份不会覆盖、也不会回滚当前的 Gist 设置。

## 自动上传：默认关

- **默认关闭。** 不填令牌，或间隔选“关闭”，定时循环都不动作；只在你点“立即上传”时才外发。
- 间隔白名单（小时）：`0（关闭）、6、12、24、168（一周）`，其他值保存时会被拒绝。
- 后台每 5 分钟检查一次是否到期；到期按“**上次尝试时间**”算（`gist_last_at`，成功失败都刷新），不是按上次成功时间算——一次失败也会把下一次尝试往后推一个间隔，不会 5 分钟一轮热重试。
- 失败时面板记日志并触发通知事件 `backup_failed`（需在[通知](./notify.md)里开启通知并勾选该事件；未勾选时唯一的失败面是 Gist 状态页的 `lastError`）。失败尝试本身按配置间隔触发（不是每 5 分钟一次），且同一失败文案在 30 分钟去重窗内只通知一次——不会每 5 分钟发一条失败通知。

## 上传规则

- 上传内容 = 与手动全量导出同一份备份（见[备份](./nodes.md#备份)），文件名 **`flmx-backup.json`**，Gist 描述为“FLMX 面板备份”，**私密 Gist（`public: false`）**。私密只表示不公开列出：**拿到 Gist 链接的人仍能看到备份内容**——这正是加密必填的原因，私密绝不等于加密。
- 导出时配置键按分类过滤：**未分类的配置键**（例如经 API 写过的自定义键）按默认敏感口径被**静默剔除**、不进备份文件，导出回执也不逐项点名；导入方向则保留未分类键，双向口径不对称——经 API 写过自定义配置键的用户，不要指望它随备份迁移。
- 首次上传创建新 Gist，以后每次上传 PATCH 同一个 Gist、产生一个新版本；若该 Gist 已在 GitHub 侧被删，PATCH 404 后面板会清空旧 id 并重新创建（历史版本随旧 Gist 一并消失，见[删除与断开](#删除与断开)）。
- **未变化跳过**：面板对“去掉导出时间的稳定序列化 + 密码”算哈希，与上次上传的哈希相同则跳过、不产生新版本；手动“立即上传”同样不强制，不变时返回“内容没有变化，没有产生新版本”。
- 单份备份明文超过 **20 MB** 拒绝上传；单次 GitHub 请求超时 60 秒，前端上传操作超时 120 秒。超大面板导出 + 上传可能超时，超时后 `lastError` 会记录，属可观测失败。
- 保存时的字段语义（与上游一致）：令牌 / 密码留空 = 保留已存值；`clearToken` / `clearPassword` = 清除；清除令牌即关闭自动上传。令牌、密码限 255 字，令牌禁空白字符。

## 版本与恢复

- 版本列表取 Gist 历史的**最近 10 个版本**（版本号 + 提交时间）。
- 恢复时按指定版本取文件 → 用上传时的密码解密 → 按 FLMX 的 **18 段全集**全量导入（T-3 口径；计数口径为备份线格式的**顶层段键**）：用户、节点、隧道、规则、用户隧道权限、限速规则、隧道分组、用户分组、分组权限、系统配置、内核与入站、用户入站分配、公告、监控权限、订阅分配、监控定义、节点 SSH 配置、联邦共享定义。段键名依次为 `users`、`nodes`、`tunnels`、`forwards`、`userTunnels`、`speedLimits`、`tunnelGroups`、`userGroups`、`permissions`、`configs`、`inbounds`、`userInbounds`、`announcements`、`monitorPermissions`、`userSubscriptions`、`serviceMonitors`、`nodeSSHConfigs`、`peerShares`。
- 其中 `nodeSSHConfigs` 与 `peerShares` 不单独构成导入/导出的「段类型」（段类型共 16 类），而是随 `nodes` 段一并导出、恢复的独立顶层段键，故顶层段键共 18 个。两段内容敏感：`nodeSSHConfigs` 是各节点的 SSH 连接配置（含凭据）、`peerShares` 是联邦共享定义——备份文件因此与节点 secret、订阅 token 同敏感级，恢复后这两类数据也会一并回来，不要按「备份不含 SSH 配置」估计泄露面。
- Gist 恢复走与本地文件导入**同一条导入尾链**：计量对账、配置缓存失效、内核重推、撤销清理、转发重推（含限速段与用户隧道段的重推），缺一不可。**与本地文件导入同口径，Gist 恢复在改写数据库之前也会先生成一份恢复前自动快照**：只落服务端文件（权限 0600、只保留最新一份、24 小时有效）；快照生成失败只记警告并继续恢复，警告随恢复回执披露（现有库已损坏导致导出失败时，用户正是最需要恢复的场景，不能因此中断）。SEC-01 废止的是把整库快照塞进回执的旧形态（泄露凭据、且导入失败时从不用它回滚）——快照字节绝不进回执、日志与错误信息。自动快照之外，恢复前再手动下载一份备份仍建议作为双保险。
- 恢复的取消口径与本地导入一致（两相位）：下载与解密完成、开始写入之前关页或断网，整单取消、不产生任何改动；**一旦开始写入，服务端会整单跑完**，关页/断网既不影响结果、也无法取消，恢复结果请重新进入页面核对。Gist 恢复与本地导入共用同一把导入互斥：任一导入/恢复进行中时，另一路会直接提示「已有备份导入正在执行」，不会并发叠写。
- 恢复前请先确认密码。解密环节的报错分四种，对照排障：加密备份未填密码，报“这个版本是加密的，请输入上传时用的密码”；密码填错、或密文在解密校验环节对不上，报“密码不对，或者数据已损坏”；信封里的 salt / nonce / data 本身解码失败、或 nonce 长度不对，报“加密数据已损坏”；信封标记（`encrypted-backup`）能识别、但里面的 KDF 名称不是 scrypt 或 scrypt 参数超出接受范围，报“不认识的加密格式”。注意：如果内容连信封标记都对不上，它不会报上面任何一条——会按明文备份直通，最终报“备份版本为空，拒绝恢复”或“备份内容不是合法的备份 JSON”；遇到这类报错，先检查是不是选错了版本或文件已损坏。

## 删除与断开

- 在面板侧清除令牌，**只断开面板侧的指向，不会删除 GitHub 上的 Gist 及其历史版本**。要彻底清除已上传的备份历史，必须登录 GitHub 网页端手动删除该 Gist。若该 Gist 已在 GitHub 侧被删，下次上传遇 404 会自动重建新 Gist（旧版本历史随旧 Gist 一并消失）。
- 同理，面板侧删除备份文件、恢复旧备份，都不影响 GitHub 侧已产生的 Gist 版本。

## 配置键

面板配置表里的 8 个 `gist_*` 键（通用配置接口不可改、只走 Gist 专用端点；备份文件里不含它们）：

| 键 | 含义 |
|---|---|
| `gist_token` | GitHub 令牌（凭据，不下发前端） |
| `gist_password` | 加密密码（凭据，不下发前端） |
| `gist_id` | 已建 Gist 的 id（首次上传后写回） |
| `gist_interval_hours` | 自动上传间隔（小时，白名单见上） |
| `gist_last_at` | 最近一次上传尝试（Unix 毫秒，成功失败都写） |
| `gist_last_upload` | 最近一次产生新版本的上传（Unix 毫秒） |
| `gist_last_error` | 最近一次失败信息（截断 255 字） |
| `gist_last_hash` | 上次上传内容的哈希（用于未变化跳过） |

专用端点（全部 POST、仅管理员、复用 `{code, msg, data, ts}` 信封）：

| 端点 | 作用 |
|---|---|
| `/api/v1/backup/gist/status` | 返回 `configured` / `tokenHint` / `encrypted` / `intervalHours` / `gistUrl` / `lastAt` / `lastUpload` / `lastError`（绝不返回令牌、密码、哈希） |
| `/api/v1/backup/gist/save` | 保存设置（先校验新令牌，间隔白名单校验） |
| `/api/v1/backup/gist/upload` | 手动立即上传（非强制，未变化跳过） |
| `/api/v1/backup/gist/versions` | 列出最近 10 个版本 |
| `/api/v1/backup/gist/restore` | 按版本取回、解密、全量导入 |

## 高级：API 基地址

默认 `https://api.github.com`。测试或自托管 GitHub API 时可用环境变量改写：`FLMX_GIST_API_BASE` 优先，`FLVX_GIST_API_BASE` 兜底（旧名前缀兼容）。**设置位置与生效方法**与 `FLMX_FETCH_*` 同口径：它是**后端进程的环境变量**，随版 `docker-compose.yml` 的 `backend` 服务默认没有它的传递行，只写部署目录 `.env` 不会生效——需在 `docker-compose.yml` 的 `backend` 服务 `environment:` 段补上 `- FLMX_GIST_API_BASE=<地址>`（或 `- FLMX_GIST_API_BASE=${FLMX_GIST_API_BASE}` 再把值写进 `.env`），再执行 `docker compose up -d backend` 重建后端容器才生效；自检：`docker exec <后端容器> printenv FLMX_GIST_API_BASE` 能打印出所设值即已生效。GitHub 请求头为 `Authorization: Bearer <token>`、`Accept: application/vnd.github+json`、`X-GitHub-Api-Version: 2022-11-28`、`User-Agent: flmx-panel`；其中令牌只发往 API 基地址同源的请求与官方 API 主机（`api.github.com`），大文件 `truncated=true` 时走 `raw_url` 再取的那一腿不带令牌；401 提示“令牌无效或已过期”，403 提示“需要 gist 权限或太频繁”。
