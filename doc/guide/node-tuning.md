# 服务器调优：按带宽与延迟算缓冲区

节点调优（sysctl）新增“按线路算缓冲区”：你填入节点的套餐带宽与到主要用户的延迟，agent 按带宽 × 延迟（BDP）算出单连接缓冲区上限，并按本机内存封顶；其余调优组照常勾选应用。

> 适用版本：随 1.4.7 引入。入口与旧版相同：**节点**页 → 某节点的操作菜单 → **调优**（仅 agent 模式节点显示）。旧版调优的一般说明见[节点调优](./nodes.md#节点调优)。
> 来源说明：算式与组表同源自上游 flyx 3.3.42 的服务器调优；能力判定与版本口径按 FLMX 重做——**不设版本号硬门**，见[旧 agent 自动降级](#旧-agent-自动降级)。

## 填什么

调优弹窗里新增**带宽（Mbps）**与**延迟（ms）**两个输入：

- 带宽范围 **1–100000 Mbps**，延迟范围 **1–2000 ms**；两个都填才算一条线路参数，只填其一或超出范围时，面板与 agent 都会拒绝（不是静默用一半参数算）。
- 这两个数是**你手动填的线路参数，不是实测值**：agent 不跑 iperf3、不做带宽探测、不改默认路由、不做统计上报。填套餐带宽与到主要用户的往返延迟即可；延迟估不准时宁可按偏大一档填，缓冲区上限随之偏大、受内存封顶约束。
- 输入合法后约 500ms 防抖，面板会重新拉取状态并显示按新参数算出的上限与原因；应用时才把线路参数发给 agent。
- 算式参考 tcpfit 的推导（仅借用算式；不采用其实测带宽、出向整形与初始拥塞窗口改动）。

## 算式（T-5 默认值：1000 Mbps / 150 ms）

设 `MiB = 1<<20`，内存取节点 `/proc/meminfo` 的 `MemTotal`：

```
BDP     = 带宽(Mbps) × 1_000_000 / 8 × 延迟(ms) / 1000        （字节）
BufMax  = 2 × BDP + 2 MiB                                    （原因“带宽 × 延迟 × 2 + 2MB”）
预算     = 内存 / 32，上限 256 MiB；内存 > 0 且 BufMax > 预算 → BufMax = 预算（原因“受内存限制”）
下限     = 4 MiB；BufMax < 4 MiB → BufMax = 4 MiB（原因“最低 4MB”）
           注意：下限在封顶之后算，4 MiB 可突破内存预算——小内存机仍保底 4 MiB
BufDef  = 1 MiB                                              （连接起始缓冲）
tcp_mem = 内存页数（内存 / 4 KiB）的 1/16、1/8、1/4 三档（页单位），
          下限分别钳制 4096 / 8192 / 16384 页
```

算例（与实现测试表一致）：

| 线路 | 内存 | 结果 |
|---|---|---|
| 1000 Mbps × 150 ms（默认值） | 2 GiB（未触内存 cap） | BDP = 18,750,000 B ≈ 17.9 MiB → BufMax = 39,597,152 B ≈ 37.8 MiB |
| 1000 Mbps × 150 ms | 512 MB | 预算 = 16 MiB → BufMax 被压到 16 MiB（原因“受内存限制”） |
| 100 Mbps × 50 ms | 任意 | BufMax 落到 4 MiB 下限（原因“最低 4MB”） |
| 100000 Mbps × 2000 ms | 64 GiB | 封顶 256 MiB；同线路在 512 MB 机上封顶 16 MiB |
| 读不到内存时 | 未知（`ramMB = 0`） | 不做内存封顶、不出现 0 缓冲，只吃 4 MiB 下限与 `tcp_mem` 下限 |

**默认值与记忆**：不填线路参数时，agent 先取上次应用值（`/etc/flux_agent/tuning-params.json`），无上次值时用默认 **1000 Mbps / 150 ms**。只发组、不带线路参数的旧式应用，同样按“上次值 / 默认值”算——这就是升级后首次应用行为变化的来源，见[升级后首次应用](#升级后首次应用)。

## 缓冲区落到哪些 sysctl

生效值写入 `/proc/sys` 并持久化到 `/etc/sysctl.d/99-flmx-tuning.conf`（旧名 `99-flvx-tuning.conf` 残留会在应用时清理，避免旧文件字典序覆盖新值）；应用前各参数原值存 `/etc/flux_agent/tuning-backup.json`（0600 惯例）。`AtLeast = true` 表示“只升不降”：当前值已高于目标时不动。

| 组 | 键 | 新值 |
|---|---|---|
| 缓冲区（旧名“加大缓冲区”，现按带宽和延迟设缓冲区） | `net.core.rmem_max` / `net.core.wmem_max` | BufMax（AtLeast） |
| | `net.ipv4.tcp_rmem` / `net.ipv4.tcp_wmem` | `4096 <BufDef=1MiB> <BufMax>`（AtLeast；`tcp_wmem` 中间值随本次由 65536 改为 1 MiB，与 `tcp_rmem` 对齐） |
| | `net.ipv4.tcp_mem` | 三档页数（AtLeast，**本次新增**，旧版无此键） |
| | `net.ipv4.udp_rmem_min` / `net.ipv4.udp_wmem_min` | `16384`（AtLeast，不变） |
| BBR | `net.core.default_qdisc=fq`、`net.ipv4.tcp_congestion_control=bbr` | 不变；**新增** BBR 模块开机加载（`modprobe tcp_bbr` + 写 `/etc/modules-load.d/flmx-bbr.conf`） |
| TCP | `tcp_fastopen=3`、`tcp_slow_start_after_idle=0`、`tcp_mtu_probing=1` | 不变；**删除** `tcp_notsent_lowat=16384`（低核机压吞吐）；`tcp_fin_timeout` 30→**15**；**新增** `tcp_tw_reuse=1`、`tcp_keepalive_time=600`、`tcp_syncookies=1` |
| 高并发队列 | somaxconn / netdev_max_backlog / tcp_max_syn_backlog / nf_conntrack_max | 不变；**新增** `net.ipv4.ip_local_port_range = 10000 65535`（非 AtLeast，固定值；旧版无此键） |
| IPv4 转发 / 文件句柄上限 | ip_forward / file-max / nr_open | 不变 |

**改小也会生效**：面板此前调过的键有备份记录，换一条更小的线路参数后，已调缓冲会被改小（例如 39.6 MB → 4 MiB 下限）；“只升不降”只对从未被本面板调过的键生效。**取消勾选某组或点“恢复默认”**，该组键恢复备份原值；旧版设过、新版不再设的键（如 `tcp_notsent_lowat`）同样在下次应用时按备份键全集恢复原值；恢复默认时还会清掉参数文件与 BBR 自载文件。写入改为原子写（临时文件 + rename），避免 conf 写一半。

**出站端口范围提醒**：勾选高并发队列组会把出站临时端口范围钉死为 `10000–65535`。若节点上有出站连接依赖 10000 以下临时端口的特殊服务，应用该组前请先确认——这是上游同提交带来的行为，不是 FLMX 自创。

## 旧 agent 自动降级

**没有版本号硬门。** 判定只看能力：面板向 agent 要调优状态，状态里带不带 `params`（实际生效的线路参数）决定界面——

- 带 `params`：新 agent，显示带宽 / 延迟输入框与算出的上限、原因，应用时带线路参数。
- 不带 `params`：旧 agent，**不显示输入框、不发送线路参数，其余调优功能照常可用**；旧 agent 按旧固定值工作：缓冲区组 `rmem_max / wmem_max = 67108864`（64 MB），`tcp_rmem = 4096 131072 67108864`，`tcp_wmem = 4096 65536 67108864`，其余 5 组按旧值，不报错、不拒绝调优。
- 第二层兜底：旧 agent 对调优命令里不认识的 JSON 字段天然忽略（Go `json.Unmarshal` 默认丢弃未知字段），即使新面板误把线路参数发给旧 agent，旧 agent 也会丢弃它们、按固定值应用。

远端（联邦）节点同理：面板拿不到可确认的能力信号时，只降级为固定值、不出错；远端路径的版本来源未单独钉死，见报告的待复核项。

## 升级后首次应用：默认值变化提示

**升级前调过、升级后第一次再点应用的节点请注意**：旧 agent 时代没有参数文件，升级后首次应用若不填线路参数，agent 会用默认 **1000 Mbps / 150 ms** 计算（2 GiB 机约 39.6 MB），**不再是旧固定值 64 MB**。请在首次应用前先填入该节点的真实带宽与延迟；已调节点再次应用时沿用上次参数，不会每次都回默认值。

自行构建 agent 的用户另请注意：本地源码构建默认上报 `dev` 版本串，面板无法从中确认能力时按不支持处理、剥离线路参数（走固定值路径，与旧 agent 降级一致）。经面板路径验证 BDP 计算时，请以正式版号构建 agent；agent 直连测试不受此限。

## 面板与 agent 接口

- 面板请求体新增 `bandwidthMbps` / `rttMs`；任一非 0 即校验双字段范围（1–100000 / 1–2000，非法拒）；`restore` 不带线路参数；调优组白名单（`bbr` / `buffer` / `tcp` / `backlog` / `forward` / `files`）与原有 30 秒超时保持不变。
- agent 状态回包新增可选字段 `params`（实际生效的线路参数）与 `sizes`（`ramMb` / `bdp` / `bufMax` / `bufDefault` / `bufReason` / `tcpMem`）；旧面板、旧前端收到多余字段按 JSON 语义忽略。

## 一键测算（建议值回填，不自动应用）

调优弹窗里另有**一键测算**：点按后 agent 探测并给出带宽 / 延迟建议值，只回填到你尚未手动改过的输入框；采纳建议值仍须你显式点击应用，探测本身绝不写盘、不改 sysctl。

- 延迟：取节点已建立 TCP 连接的内核 RTT 中位数（sock_diag）；取不到时明确报不可用并回落默认值 150 ms，不编造数值。
- 带宽：默认不测速；只有当你提供测速地址时才对该地址做短时测速（10 秒 / 64 MiB 上限），未提供地址时明确报不可用并回落默认值 1000 Mbps。
- 每腿独立回落且必明示原值与警告；探测失败只填空字段，不覆盖你已填的值。
- 超时链：agent 约 25 秒 < 面板 90 秒 < 前端 120 秒；探测接口仅管理员可用。
