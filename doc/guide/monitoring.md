# 监控

**监控** 页集中看三类状态：节点监控、服务监控、隧道质量。监控发现的异常（掉线、探测失败、延迟劣化等）会经 [通知](./notify.md) 推送，本文只讲监控面本身。

## 节点监控

按节点列出在线状态与运行指标（连接状态、版本、流量与资源占用等），与 **节点** 页的卡片信息同源，这里是跨节点的总览视角，适合节点多时快速扫一遍有没有异常。

## 服务监控

对任意目标做定时连通性探测，适合盯落地机端口、第三方服务或某个 IP 是否可达：

- **类型**：TCP（端口连通）、ICMP（ping）、HTTP（请求状态）；
- **经节点探测**：TCP / ICMP 可以指定由某个节点上的 agent 发起探测，测的是「从该节点出发」的连通性；不指定时由面板侧探测；
- **间隔与超时**：每项可单独设探测间隔与超时（超时最大 60 秒）；可以随时 **立即执行** 一次，不等下一轮；
- **启用 / 停用**：停用的探测不再执行，历史结果保留；
- 探测结果（成功/失败、耗时）会留存并可回看，连续失败会触发通知事件。

## 隧道质量

逐跳探测每条隧道的连通与延迟（入口 → 中间跳 → 出口），定位多跳线路里是哪一段出问题。隧道质量探测默认开启，探测间隔在 **网站配置** 的监控设置里可调。

## 监控权限

监控页默认只有管理员能看。管理员可以在 **网站配置** 里把监控的**查看权限**分配给指定的普通用户（监控权限分配），被授权用户登录后能打开监控页看状态，但不能改监控配置、不能执行管理操作。

## 数据保留

监控类数据（探测结果、质量样本等）的保留天数在 **网站配置** 里可设，过期数据自动清理。需要长期留档的指标请用每日汇总通知或自行导出。
