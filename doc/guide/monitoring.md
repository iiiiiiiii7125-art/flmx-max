# 监控

监控分三类：节点监控、服务监控、隧道质量。入口按角色分开：

- **管理员**没有独立的「监控」菜单——从 **节点** 页逐个节点打开监控（实时指标、历史曲线、该节点的服务监控），隧道质量从 **中转** 页的 **质量** 标签看；直接访问 `/monitor` 会跳回节点页。
- **被授予监控权限的普通用户**有独立的 **监控** 总览页，但只能看自己可达隧道的隧道监控与隧道质量（见下「监控权限」）；节点监控与服务监控对普通用户整体关闭。

本文只讲监控面本身；哪些异常会经 [通知](./notify.md) 推送，以通知页的事件清单为准。

## 节点监控

按节点列出在线状态与运行指标（连接状态、版本、流量与资源占用等）。管理员在节点列表里点开单个节点的监控看明细。节点监控仅管理员可见——普通用户（含被授予监控权限的用户）没有这个页面，其监控总览页里也不包含节点状态。

## 服务监控

**仅管理员**：服务监控的查看、配置与执行都只对管理员开放，普通用户（含被授予监控权限的用户）整体不可见。

对目标做定时连通性探测，适合盯落地机端口、第三方服务或某个 IP 是否可达。**目标的拒绝口径按执行面分两层，不要混读**：

- **面板本机执行**（TCP 且未指定节点，由面板进程直接拨号）：按**非公网全集**拒绝——回环、私网、链路本地、CGNAT、组播、保留段等一切非公网目标（域名解析到任一非公网地址同样拒绝），外加硬拒集；只有公网目标能测。要盯内网/LAN 里的服务，用下面的经节点探测。
- **经节点执行**（指定了执行节点）：只拒**硬拒集**（云元数据精确地址、链路本地段 `169.254.0.0/16`、未指定地址、本地 NAT64 段），在保存、下发、执行三面都会被拒绝；私网/回环等非公网目标放行——节点监控其所在 LAN 服务正是这个执行面的正当用途。

两种执行面的具体形态：

- **类型**：TCP（端口连通）、ICMP（ping）；
- **经节点探测**：TCP / ICMP 可以指定由某个节点上的 agent 发起探测，测的是「从该节点出发」的连通性；TCP 可不指定节点（面板侧探测）；ICMP 必须指定执行节点；
- **间隔与超时**：每项可单独设探测间隔与超时（超时最大 60 秒）；可以随时 **立即执行** 一次，不等下一轮；
- **系统级限值**：服务监控另有一组系统级限值（配置键 `service_monitor_*`，经限值接口下发、保存时按值域校验）：检查器扫描间隔默认 1 秒、并发上限默认 20（保存上限 50）、单项间隔最小/默认 1 秒、单项超时最小 1 秒 / 默认 5 秒 / 最大 60 秒（三个超时键保存时都不得超过 60）。大规模配置时探测的实际并发与节奏受这组限值约束，不是每项都独立全速跑。
- **启用 / 停用**：停用的探测不再执行，历史结果保留；停用只停调度，立即执行对停用项同样可用；两个查看面的口径不同，不要混读：**总览**只显示启用中的监控的最新结果，停用（或已删除）项的最新结果会从总览消失；**逐项历史**不做这层过滤，停用项此前的结果仍从该项的历史记录里查看；
- 探测结果（成功/失败、耗时）留存并可回看。

## 隧道质量

逐跳探测每条隧道的连通与延迟（入口 → 中间跳 → 出口），定位多跳线路里是哪一段出问题。隧道质量探测默认开启，探测间隔在 **网站配置** 的监控设置里可调。

**UDP 例外**：上面的逐跳定位只适用于 **TCP 协议段**。目标段为 UDP 协议时，该段**不做连通 / 延迟实测**——UDP 没有通用回声协议，拿 TCP 去测 UDP 监听只会恒失败、把健康链路误读成死链。这类跳在质量视图里记为「**未测**」（逐跳条显示「未测 / UDP 未测」）：它不判失败、不计入整条隧道的延迟 / 丢包聚合，也不会参与最优出口评分。其内部数值是未测哨兵（延迟 `-1`、丢包 `100`），**不是实测结果**——看到 UDP 段显示这两个数值不要按故障处理，该段无错误信息且丢包列显示「-」时即属此情形。自检法：隧道里某一段恒显示「未测」时，先看该段协议是不是 UDP，是则属预期行为；要定位 UDP 段是否真通，只能靠实际业务流量或手动诊断之外的手段验证。

## 手动诊断

除自动的质量探测外，隧道与转发都可以**手动发起一次诊断**，当场逐项检查各段的运行态与连通性：

- **入口**：隧道诊断在 **中转** 页 → **隧道** 标签，每条隧道操作列的「**诊断**」按钮（仅管理员）；转发诊断按角色分开：管理员在 **中转** 页 → **规则** 标签（即转发列表），普通用户没有中转页、在独立的 **规则** 页（转发列表）操作——两边都是每条转发操作列的「**诊断**」按钮，普通用户只能诊断自己名下的转发。
- **呈现方式（流式）**：诊断弹窗首选**流式**执行：点诊断后逐项实时回显结果与进度（已完成 / 总数，以及成功、失败、未验证三类计数），不用等全部跑完才出结果；流式不可用时自动回退为一次性请求，最终结果口径一致。超时口径为单条 30 秒 / 整体 2 分钟，超时会保留已完成的结果并明确标注，不会整单丢弃。
- **目标腿只测 TCP**：转发诊断的最后一腿（到目标地址）只做 TCP 探测，**没有 UDP 目标探测项**——目标是 UDP 服务时这一腿实际按 TCP 测、多呈失败，按下面的「失败」口径理解即可，不要等它出现「未验证」。
- **「未验证」与「失败」的区别（关键）**：
  - **未验证**：出现在**链路段的 UDP 传输腿**探测项上。UDP 无通用回声协议、无法实测连通性，面板把这类项单列为「未验证」（文案为「UDP 无法实测连通性（无通用回声协议），本项未验证」），呈中性样式，延迟 / 丢包显示为未测（空值），**既不计成功也不计失败**。看到「未验证」只说明这一项测不了，不代表线路坏了。
  - **失败**：真实测出或真实发生的错误才记失败——例如 TCP 拨号不通、目标不可达，以及与协议无关的探测前错误（DNS 解析失败、命令级执行失败等；UDP 项遇到这类错误同样记失败，不会被「未验证」豁免）。失败项带具体错误信息，按它定位故障段。
  - 自检法：诊断汇总里先看三类计数——失败数大于 0 才是有实测故障；只有未验证数大于 0、失败为 0 时，含义是「TCP 段都通，UDP 段无法实测」，不要按故障处理。
- **与隧道质量的关系**：手动诊断是一次性动作，结果不进质量时间线；质量标签里的 UDP 段恒为「未测」呈现（见上节），与诊断里的「未验证」是同一口径的两种呈现，不要把质量页的「未测」读成诊断失败。

## 监控权限

管理员不需要授权，直接从节点页 / 中转页进入。普通用户未获授权时，菜单里的 **监控** 项始终可见但置灰、点击会提示无权限（只是入口摆在那里，没有功能越权）；管理员在 **用户** 页给指定用户授予**监控权限**后，该项才可用、进入 **监控** 总览页——能看的只有**自己可达隧道的隧道监控与隧道质量**，节点监控与服务监控不对普通用户开放（接口会直接返回 403）。授权不包含任何配置修改或管理操作权限。

## 数据保留

监控类数据（探测结果、质量样本等）的保留天数在 **网站配置** 里可设（字段 `monitor_retention_days`，默认 7 天），过期数据自动清理。需要长期留档的指标请用每日汇总通知或自行导出。

- **入站连接日志独立保留**：连接日志的保留天数是独立配置键 `connlog_retention_days`，可填 1–30 天，默认 7 天；与上面的 `monitor_retention_days` 是两个独立键，互不影响。另有每入站 5 万行的行数上限，超期或超量自动清理（见 [节点 · 入站连接日志](./nodes.md#入站连接日志)）。

两条例外不在上面的可设口径内：

- **节点延迟样本硬封顶 7 天**：延迟样本量大，其保留期取「配置保留天数与 7 天中的较短者」——把保留天数调到 7 天以上，节点 / 隧道指标、服务监控结果与质量样本会按新值留存，但**延迟历史仍只留 7 天，调大不生效**（调小则按较小值）。在监控页把延迟曲线拉到 7 天以前看不到数据属预期，不是数据丢失。
- **节点流量小时桶固定 400 天**：节点流量的小时级汇总桶独立保留 **400 天**，不随保留天数配置变化（调小保留天数也不会把流量桶提前清掉）。
