# 通知

在 **网站配置 → 通知** 里填写 Telegram 机器人或 Webhook 地址（两个都填就都发），打开 **启用通知** 后保存。点 **发送测试** 可以先用当前填写的内容试发一条，不用先保存。

## 事件

| 事件 | 什么时候提醒 |
|------|--------------|
| 节点掉线 / 恢复 | 节点断开超过 90 秒才提醒，重启、升级等短暂断线不打扰；重新连上后再发一条恢复 |
| 导入节点连不上 / 恢复 | [连通性检测](./import.md#连通性检测) 连续两次失败（约 6 分钟）才提醒，恢复后再发一条 |
| 内核运行出错 | 节点上的 Xray / sing-box / Snell 状态变成出错时提醒，附带错误信息 |
| 延迟 / 丢包异常 / 恢复 | 节点到某个测试点连续 3 轮探测劣化（丢包率或延迟达到阈值）时提醒一次，恢复后再发一条 |
| 回程线路变化 | 节点的回程线路识别结果与上次相比发生变化时提醒（IPv6 线路变化单独一行） |
| 节点即将到期 | 节点设置了到期时间，到期前 3 天内提醒一次（在节点页关掉到期提醒的节点不会提醒） |
| 用户流量 / 到期 | 转发用户流量用到 90%、用完，或 3 天内到期；[分享订阅](./subscription.md#流量上限) 流量用到 90%、用完，或 3 天内到期 |
| 每日汇总 | 每天在设定的时间发一条：节点在线数、内核出错数、导入节点连不上的数量、入站和转发流量、分享订阅情况 |
| Gist 备份失败 | [Gist 备份](./gist-backup.md)定时上传失败时提醒，失败详情见 Gist 状态里的 `lastError` |

同一个问题只提醒一次，恢复后才会再次提醒。不想收的事件取消勾选即可。全部取消时，后端会把事件配置 `none` 视为"不启用任何事件"（O8-006 兼容说明：旧版本前端就是靠这个字面量表示全不选的）。

面板重启后，之前已掉线的节点会在启动扫描时补发一条"面板重启后仍离线"，不会因为重启而漏报。发送失败的通知会在单次发送内按通道分别重试一次；仍然失败的**不会记为已发送**，会在后续检查中补发（每日汇总同理，在同一小时内的后续检查中补发）。补发只补未送达的通道：通道级送达台账已落地且为全部事件共用，正常运行时发送失败只补发未成功送达的通道，已经成功的通道不会重复收到。需要注意的是，台账为进程内存态：若在部分通道已送达、其余待补发期间重启面板，待发状态会丢失并按最新累计值重算重发，已送达通道可能多收一份重算版日报，其余事件同理可能多收一份原文。

每日汇总默认早上 9 点发送，可以在 **每日汇总发送时间** 里改（0–23 点）。时间按面板服务器的时区，安装脚本默认 `Asia/Shanghai`。

## Telegram

1. 找 [@BotFather](https://t.me/BotFather) 发 `/newbot` 创建机器人，拿到 Bot Token（形如 `123456:ABC-DEF...`）
2. 给你的机器人发一条消息（或把它拉进群），再用 [@userinfobot](https://t.me/userinfobot) 查自己的 Chat ID；群组的 ID 以 `-100` 开头
3. 填入面板，点 **发送测试**

面板服务器在国内、连不上 `api.telegram.org` 时，可以在 **Telegram API 地址** 里填一个反代地址（例如 Cloudflare Workers 反代），面板会请求 `<地址>/bot<Token>/sendMessage`。

## Webhook

面板会向填写的地址发送 `POST` 请求，内容是 JSON：

```json
{
  "event": "node_offline",
  "title": "节点掉线",
  "message": "节点：东京-1",
  "text": "[FLMX] 节点掉线\n节点：东京-1\n时间：2026-10-16 10:00:00 UTC",
  "time": 1792130385331,
  "app": "FLMX"
}
```

- `event`：`node_offline`、`inbound_down`、`kernel_error`、`node_expiry`、`user_quota`、`daily_report`、`latency_bad`（延迟/丢包异常与恢复）、`route_change`（回程线路变化），测试消息是 `test`
- `text`：拼好的完整文本，直接转发给企业微信、钉钉、Bark、Server 酱等服务时用它即可
- `time`：毫秒级 Unix 时间戳（数字，不是格式化字符串）；带时区的格式化时间在 `text` 字段里
- 返回 2xx 视为发送成功
- 出站地址口径：指向云元数据服务（如 `169.254.169.254`）的地址会被明确拒绝；内网地址默认放行——把 Webhook 发到内网的企业微信/告警网关是预期用法

Bot Token 和 Webhook 地址只有管理员能看到，也不会写进 JSON 备份。

## 公告（站内）

与上面的站外通知不同，**公告**是给登录面板的用户看的站内消息：在 **网站配置 → 公告** 里编辑（支持 Markdown），启用后：

- 所有用户登录后会在总览页顶部看到公告**横幅**，可手动关闭；
- 公告还会以**弹窗**形式呈现一次，用户可以关闭、或勾选「不再显示」让这条公告不再弹窗；
- 内容有更新时重新发布，用户会重新看到新公告。

公告内容包含在 JSON 备份里（见备份说明），换机恢复后一并还原。
