# 通知

在 **网站配置 → 通知** 里填写 Telegram 机器人或 Webhook 地址（两个都填就都发），打开 **启用通知** 后保存。点 **发送测试** 可以先用当前填写的内容试发一条，不用先保存。

## 事件

| 事件 | 什么时候提醒 |
|------|--------------|
| 节点掉线 / 恢复 | 节点断开超过 90 秒才提醒，重启、升级等短暂断线不打扰；重新连上后再发一条恢复 |
| 导入节点连不上 / 恢复 | [连通性检测](./import.md#连通性检测) 连续两次失败（约 6 分钟）才提醒，恢复后再发一条 |
| 内核运行出错 | 节点上的 Xray / sing-box 状态变成出错时提醒，附带错误信息 |
| 延迟 / 丢包异常 / 恢复 | 节点到某个测试点连续 3 轮探测劣化（丢包率或延迟达到阈值）时提醒一次，恢复后再发一条 |
| 回程线路变化 | 节点的回程线路识别结果与上次相比发生变化时提醒（IPv6 线路变化单独一行） |
| 节点即将到期 | 节点设置了到期时间，到期前 3 天内提醒一次（在节点页关掉到期提醒的节点不会提醒） |
| 用户流量 / 到期 | 转发用户流量用到 90%、用完，或 3 天内到期；[分享订阅](./subscription.md#流量上限) 流量用到 90%、用完，或 3 天内到期；用户[日/月配额](./forward.md#日-月配额)用到 90%、用完时同样提醒，配额解除（窗口滚动或手动重置）后发一条恢复 |
| 每日汇总 | 每天在设定的时间发一条：节点在线数、内核出错数、导入节点连不上的数量、入站和转发流量、分享订阅情况、日/月配额超额用户数（无超额时不显示该行）。因无数据或查询失败而未列出的行会在文末统一补一行 `未列出：行（原因）、…`（例如 `未列出：节点在线（无节点）、内核出错（无内核记录）`）；没有任何行可列时正文只有 `暂无数据` 加这一行 |
| 连接跟踪表用量过高 | 节点 conntrack 表用量达 80% 时提醒，表满后内核丢弃全部新数据包；回落到 70% 以下解除并重新武装 |
| 磁盘用量过高 | 节点或面板根盘用量达 80% 时提醒；回落到 70% 以下解除并重新武装 |
| agent 内存用量过高 | 节点 agent 进程内存（RSS）用量达整机内存 80% 时提醒；回落到 70% 以下解除并重新武装 |

同一个问题只提醒一次，恢复后才会再次提醒。不想收的事件取消勾选即可。全部取消时，后端会把事件配置 `none` 视为"不启用任何事件"（O8-006 兼容说明：旧版本前端就是靠这个字面量表示全不选的）。

表末三项资源告警（连接跟踪表 / 磁盘 / agent 内存）有**独立开关**（通知设置里的「资源告警」区，配置键 `notify_conntrack_high` / `notify_disk_high` / `notify_agent_memory_high`，缺省开启）：它们不走上方事件勾选——取消任一事件、乃至全部取消（`none`），都不会关掉资源告警；要停用某项资源告警，取消它自己的勾选。只有关掉 **启用通知** 总开关才会停掉全部通知。

面板重启后，之前已掉线的节点会在启动扫描时补发一条"面板重启后仍离线"，不会因为重启而漏报。发送失败的通知会在单次发送内按通道分别重试一次；仍然失败的**不会记为已发送**，会在后续检查中补发（每日汇总同理，在同一小时内的后续检查中补发）。补发只补未送达的通道：通道级送达台账已落地且为全部事件共用，正常运行时发送失败只补发未成功送达的通道，已经成功的通道不会重复收到。需要注意的是，台账为进程内存态：若在部分通道已送达、其余待补发期间重启面板，待发状态会丢失并按最新累计值重算重发，已送达通道可能多收一份重算版日报，其余事件同理可能多收一份原文。

每日汇总默认早上 9 点发送，可以在 **每日汇总发送时间** 里改（0–23 点）。时间按面板服务器的时区，安装脚本默认 `Asia/Shanghai`。

### 延迟 / 丢包阈值

在 **网站配置 → 通知** 里勾选 **延迟 / 丢包异常** 事件后，下方会展开 **延迟 / 丢包阈值** 字段组。两个字段都填整数：

| 字段 | 配置键 | 填法 | 留空时 |
|------|--------|------|--------|
| 丢包率 ≥（%） | `notify_latency_loss_pct` | 整数 1–100 | 默认 20 |
| 延迟 ≥（ms） | `notify_latency_ms` | 整数，大于 0 才启用延迟判断 | 0＝不判断 |

- **触发口径**：节点到某个测试点**连续 3 次检测（约 9 分钟）**丢包率 ≥ 阈值，或（延迟判断已启用时）延迟 ≥ 阈值，判为劣化并提醒一条，恢复后再发一条；测试点连不上直接算劣化，不看阈值。
- **防错**：延迟填 `0` 不是「延迟 ≥ 0 就报」，而是**关闭延迟判断**；丢包率填 `0`、超过 100 或填非整数，都不会按字面值生效，而是当作未设置、回落默认 20%。改完点保存，之后每轮检测都按新值判断。
- **自检**：把延迟阈值临时改成 `1` 保存，正常节点也会在约 9 分钟后收到一条延迟异常提醒；确认收到后改回需要的数值（或清空恢复默认）。

## Telegram

1. 找 [@BotFather](https://t.me/BotFather) 发 `/newbot` 创建机器人，拿到 Bot Token（形如 `123456:ABC-DEF...`）
2. 给你的机器人发一条消息（或把它拉进群），再用 [@userinfobot](https://t.me/userinfobot) 查自己的 Chat ID；群组的 ID 以 `-100` 开头
3. 在 **网站配置 → 通知** 里把 Bot Token 填入 **Telegram Bot Token** 字段、Chat ID 填入 **Telegram Chat ID** 字段，点 **发送测试** 验证

> Bot Token 等同机器人的钥匙：泄露后任何人都能冒充你的机器人发消息。怀疑泄露时在 BotFather 里发 `/revoke` 作废旧 Token 并换新，再回面板更新 **Telegram Bot Token** 字段。

面板服务器在国内、连不上 `api.telegram.org` 时，可以在 **Telegram API 地址** 里填一个反代地址（例如 Cloudflare Workers 反代），面板会请求 `<地址>/bot<Token>/sendMessage`。

### 机器人菜单（自主查询）

配好 Telegram 后，机器人除了收通知，还能主动查：在 Telegram 里给机器人发 `/start`，会弹出三个按钮——**🖥 节点状态**、**📊 流量**、**ℹ️ 面板状态**；也可以直接发 `/nodes`、`/traffic`、`/status` 得到同样的回答（这四个命令已在 Telegram 的命令菜单里注册）。

- **节点状态**：全部节点逐个列出，在线的标 🟢 并附最近 15 分钟内的探针延迟（过期或无探针时不显示），离线的标 🔴；末尾汇总总数与在线数。
- **流量**：今日＝自 0 点以来整点增量合计（当前不足一小时的部分未计入）；本周期＝用户流量快照合计，按月重置。
- **面板状态**：面板版本、节点总数/在线数、已运行时间。

只有 **Telegram Chat ID** 里填的那个聊天能用：别的聊天发来的消息和点的按钮一律静默忽略，不回复。通知总开关关掉时机器人菜单也不工作（轮询休眠），先打开 **启用通知**。机器人只回答这三个查询，其他文字一律忽略。

## Webhook

面板会向填写的地址发送 `POST` 请求，内容是 JSON：

```json
{
  "event": "node_offline",
  "title": "节点掉线",
  "message": "节点：东京-1",
  "text": "🔴 <b>节点掉线</b>\n节点：东京-1\n🕐 2026-10-16 18:00:00 +08:00",
  "time": 1792144800000,
  "app": "FLMX"
}
```

- `event`：`node_offline`、`node_upgrade_failed`（节点升级/回退下发后超时未回连到目标版本）、`inbound_down`、`kernel_error`、`node_expiry`、`user_quota`、`daily_report`、`latency_bad`（延迟/丢包异常与恢复）、`route_change`（回程线路变化）、`conntrack_high`（节点连接跟踪表用量达 80%）、`disk_high`（节点或面板磁盘用量达 80%）、`agent_memory_high`（节点 agent 内存用量达 80%），测试消息是 `test`
- `text`：与 Telegram 共用同一 HTML 渲染的完整文本——emoji ＋ `<b>标题</b>` ＋ 正文 ＋ `🕐` 数字时区偏移页脚（旧纯文本格式的 `[FLMX]` 前缀已去掉，也没有单独的 `时间：… UTC` 行，时间在 `🕐` 页脚里）。直接转发给企业微信、钉钉、Bark、Server 酱等纯文本渠道时，对方会原样收到 `<b>` 标签；需要纯文本时先去掉 HTML 标签，或改用 `message` 字段自己拼
- `time`：毫秒级 Unix 时间戳（数字，不是格式化字符串）；带时区的格式化时间在 `text` 字段里
- 返回 2xx 视为发送成功
- 出站地址口径：以下硬拒集会被明确拒绝——云元数据精确地址 3 个（`169.254.169.254`、`100.100.100.200` 阿里云元数据、`fd00:ec2::254` AWS IPv6 元数据）、`169.254.0.0/16` 链路本地段整段、未指定地址（`0.0.0.0`、`::`）；除此之外内网地址默认放行——把 Webhook 发到内网的企业微信/告警网关是预期用法

Bot Token 和 Webhook 地址保存后**任何角色（含管理员）都无法读回**（配置页不回显、读接口不返回明文），也不会写进 JSON 备份。
