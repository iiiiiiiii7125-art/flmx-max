# 搭建节点

在落地机上部署代理节点（入站）。所有配置由面板生成，节点上的 agent 只负责下载内核、写入配置、运行和守护进程。

> 术语对照：面板菜单里的 **落地** 页就是本文档所说的节点 / 入站管理；菜单 **规则** 在文档里称转发（见 [流量转发与管理](./forward.md)）。

## 准备

- 落地机已按 [安装部署](./install.md) 装好节点 agent，并在面板里显示在线
- Linux amd64 / arm64，root 权限
- 建议安装 nftables（`apt install nftables`）：入站流量统计、白名单和 Hysteria2 端口跳跃依赖它。一般功能没有 nftables 也能跑，但有一个例外要先知道：入站或节点开启了**白名单**时，内核启动前必须先把 nft 规则同步成功；nftables 缺失或同步失败时，受保护的内核会**整体不启动**（该内核下全部入站下线）——这是刻意的 fail-closed 口径，不是「少几个功能」的降级运行。白名单下发时 agent 会自动安装 nftables，不用手动装；装不上时内核同样 fail-closed 不启动，但面板会明示 nftables、节点与安装失败原因，不会静默

## 安装内核

**落地** 页 → **内核** 标签 → **安装内核** → 选择节点和内核。

| 内核 | 版本 | 说明 |
|------|------|------|
| Xray | 默认最新版，可指定 | 从 GitHub Release 下载，用 GitHub 接口返回的资产摘要（digest）校验，不用 Release 附带的校验文件 |
| sing-box | 默认最新版，可指定 | 从 GitHub Release 下载，用 Release 资产的 SHA256 校验 |

一台节点可以同时安装多个内核，内核按节点分组显示。点击内核可以启停、重启、查看日志、更换版本或卸载；节点重启后内核会自动恢复运行。

端口留空会随机分配，UUID、密码、密钥留空会自动生成。

| VLESS + Reality + Vision | Xray / sing-box | 推荐，无需域名和证书 |
| VLESS + XHTTP + Reality | Xray | |

| Trojan + TLS（自签） | Xray / sing-box | 需要填写域名 |

### 证书

TLS 类入站有三种证书来源：

- **自动生成自签证书**：开箱即用，客户端需要允许不安全证书（分享链接已自动带上）
- **使用节点上的证书文件**：填写证书和私钥在节点上的绝对路径
- **自动申请证书（ACME）**：仅 sing-box，需要 sing-box 1.14 及以上
  - 域名必须解析到该节点
  - HTTP 验证：节点 80 端口要能从公网访问
  - DNS 验证：支持 Cloudflare（API Token）和阿里云（AccessKey），不需要 80 端口。面板侧在入站表单的证书区选 **自动申请证书（ACME）** 后，把 **验证方式** 选为 **Cloudflare DNS** 或 **阿里云 DNS**，再按下文填凭据
  - 证书由 sing-box 自动续期

DNS 验证的凭据获取与填写（两家二选一）：

- **Cloudflare**：登录 Cloudflare 控制台 → 右上角头像 → **My Profile（我的个人资料）** → **API Tokens** → **Create Token** → 选 **Edit zone DNS** 模板（或自建令牌：权限给 **Zone → DNS → Edit**，Zone Resources 只勾选要签证书的那个域名 Zone，不要放行全部 Zone）；创建后复制 Token，填入面板的 **API Token** 字段（只有一个字段）。防错：只给 Zone 级 DNS 编辑权即可，**不要填 Global API Key**；Zone 选错或没包含目标域名会直接签发失败。自检：保存入站后看节点上 sing-box 的日志，出现证书签发成功即通；报 403 多半是 Token 权限或 Zone 范围不对，回控制台核对这两项。
- **阿里云**：登录阿里云控制台 → 右上角头像 → **AccessKey 管理** → **创建 AccessKey**，拿到 **AccessKey ID** 与 **AccessKey Secret**，分别填入面板的 **AccessKey ID** / **AccessKey Secret** 两个字段；该账号要有云解析 DNS 的读写权限（系统策略 `AliyunDNSFullAccess`，或等价的自定义策略）。防错：**Secret 只在创建时显示一次**，关掉页面就再也看不到，先保存好再填面板；AccessKey 等同账号钥匙，建议用 RAM 子账号只授 DNS 权限，不要长期用主账号 AccessKey。自检同上：看 sing-box 日志的签发结果，报权限类错误先回控制台查该账号的 DNS 授权。

两家的凭据都只存面板、保存后不回显（编辑入站时字段显示「已保存，留空不修改」，留空即保留原值）。

NaïveProxy 必须使用真实证书（ACME 或证书文件）。

### Hysteria2 端口跳跃

在 Hysteria2 入站里填写一段 UDP 端口，例如 `20000-30000`。节点会用 nftables 把这段端口转到入站端口，客户端在其中随机切换，缓解运营商对单个 UDP 端口的限速。

- 范围不能包含入站端口本身，不能和其他入站、转发或节点的转发端口段重叠
- 只有直连地址带跳跃参数；经中转连接时只转发一个端口，不跳跃

### 监听地址

默认监听 `::`（同时支持 IPv4 和 IPv6）。如果节点在内核启动参数里完全禁用了 IPv6（`ipv6.disable=1`），部分内核会绑定失败，此时在高级选项里把监听地址改为 `0.0.0.0`。

### 空闲超时（秒）

入站创建/编辑表单里的**空闲超时（秒）**：该入站连接的空闲关断窗口。留空表示不设置，走 Xray 默认 300 秒；填 `1–86400` 的整数；填 `0` 表示清除已设的值（与留空等效，恢复默认 300 秒；面板不下发显式的 0，Xray 层面 0 没有独立语义）。

- **不限**：勾选输入框旁的「不限」，该入站的连接永不因空闲自动断开。实现上存为 `-1`、渲染为 `31536000` 秒（365 天）：Xray 的关断窗口是 (N, 2N]，365 天对应实际 1–2 年才断，等同于永不断；更大的数没有意义——面板升级或节点重启本来就会断会话，且 2N 须远离 int32 上限。常驻连接（如自动客服系统）用此项；取消勾选恢复原值。

- **关断语义（上游 Xray 机制，非面板缺陷）**：Xray 的空闲计时器以设定秒数 N 为一格、按格检查——全程无数据的会话约 N 秒后断开；有过数据的会话，自末次数据起 **N–2N 秒**后断开（数据落在检查格内的位置决定具体值：刚过格线的数据约 2N 秒断，临近格线的数据约 N 秒断；实测 N=5 时带数据会话 10.2 秒断、静默会话 5.2 秒断，N=10 时带数据会话 20.2 秒断）。面板下发的 `policy.levels[].connIdle` 与 `flmx-idle-*` 出站的 `userLevel` 均与设定值逐字一致、未翻倍——2N 是上游计时粒度，不是面板多算了一倍；把下发值减半会让静默会话提前到 N/2 断开，故面板不以改值“补偿”，只按实测语义写明承诺。
- VMess/SS 的会话关断约 3.1 秒且不随设定值变化，静默约 1.1 秒——属上游 Xray-core 行为，关得比设定快，安全方向，与面板渲染无关。

- **仅 Xray 内核可用**。sing-box 内核没有 Xray 式空闲超时（TCP 靠 keepalive 保活、UDP 会话默认 5 分钟清理、仅 TUN 有 `udp_timeout`），sing-box 入站上该字段禁用并会明示原因。
- 不同入站可设不同值，互不干扰；删除入站后对应的超时配置一并撤下。

### VLESS 加密（ENC）与「IEPL专用」预设

Xray 内核的 VLESS 入站可开启 VLESS 加密（ENC）；只有套用纯 ENC 预设形态的入站（VLESS／TCP／安全无／ML-KEM-768 认证／xorpub 外观／无流控／无 SNI／空闲超时「不限」）才在列表里带红色「IEPL专用」标识，只开 ENC 开关但形态不同的入站不带此标识。流控只有一条判据：**纯 ENC 配置（ENC 开 + 安全无）不开启流控**——两条填充路径同此口径：

- 点红色的「**IEPL专用**」标签：套用纯 ENC 预设——VLESS / TCP / 安全无、ENC 开、ML-KEM-768 后量子认证、xorpub 外观、无 SNI，并同时勾选上面的空闲超时「不限」。只填表单、不创建，也不改已填的节点、端口与名称。
- 直接拨动「启用 VLESS 加密（ENC）」开关：自动套用标准配置（TCP、安全无、ML-KEM-768 认证、native 外观），同样不开启流控。

流控功能本身不受影响：VLESS Reality 等其他配置照常可以开启 XTLS Vision 流控。另外要分清：上面「纯 ENC 不开启流控」说的是两条**填充路径的预设结果**，不是后端禁令——手工编辑入站时把 ENC 与 Vision 流控组合使用是允许的（ENC 是 Vision 的合法加密层），保存与导入都不会被拒，只是没有任何预设会替你这样填。

### 出站

服务器侧的分流和链式：客户端照常连本节点，由节点内核决定流量从哪里出去。

点入站 → **出站**，有两部分（对话框顶部还能设置出站 IP 策略，见 [出站 IP 策略](#出站-ip-策略)）：

- **默认去向**：直连（从本节点出去），或选另一个入站（其他节点上的入站、导入的节点），流量再经它出去，网站看到的是它的 IP（链式代理）
- **分流规则**：按目标把一部分流量送到别处，从上到下匹配，先命中先生效，都不命中的走默认去向

每条分流规则选分类或填自定义域名 / IP，再选去向：**直连**、**阻断** 或某个出站节点。

| 分类 | 内容 |
|------|------|
| 流媒体 | Netflix、Disney+、YouTube、HBO、Prime Video、Spotify、TikTok |
| AI | ChatGPT、Claude、Gemini |
| 常用 | Google、Telegram |
| 其他 | 广告、BT 下载、回国流量（中国大陆的域名和 IP） |

常见用法：

- 只让 Netflix / ChatGPT 走有解锁 IP 的节点（例如导入的机场节点），其他流量照常直连
- 落地机阻断 BT 和回国流量，避免被投诉或滥用
- A → B → C 多级：给 A 的入站选 B 作为默认去向，再给 B 的入站选 C；每个节点只连下一跳
- 自定义域名包含子域名，例如填 `example.com` 也匹配 `www.example.com`

注意事项：

- 分类数据自动更新：Xray 用 v2fly 的 geosite / geoip 数据，由节点 agent 经内置的 GitHub 下载路线自动测速直选下载（先测直连，直连不通才按延迟在内置代理候选中选最快；直连虽通但探测延迟超过 800ms 时不算短路，会与代理候选同场按延迟排名、可能改走更快的代理——与 [升级指南](./upgrade.md) 的 agent 侧 800ms 边界口径一致，无需在面板里配置加速地址），节点每天检查一次，有新版本就下载、校验后替换并重启 Xray（启动失败会恢复原文件），内核日志里可以看到更新记录；sing-box 的分流规则集走同一条路线：由节点 agent 经内置的 GitHub 下载路线测速选线预下载（下载时校验规则集文件格式，假活/错误页会被判失败换线），落盘后以本地规则集形式交给 sing-box 加载，agent 还会周期性检查规则集更新（内容有变化才替换并重启）——因此 sing-box 分流**不要求落地机直连访问 GitHub**；规则集下载失败且本地没有可用副本时，本次配置下发会在写盘前中止、继续使用上一次能运行的配置（见下），已有副本时刷新失败会沿用旧副本并在内核日志中记录
- Xray 能连接 VLESS / VMess / Trojan / Shadowsocks（不含插件和 ShadowTLS）/ SOCKS5 / HTTP 出站节点；Hysteria2、TUIC、AnyTLS 等请用 sing-box 内核
- 出站节点是本面板的自签证书入站时，Xray 用证书指纹校验；导入的节点如果跳过了证书验证，Xray 无法连接（新版 Xray 已移除 `allowInsecure`），请改用 sing-box
- 开启了“获取真实客户端 IP”的入站只能经中转连接，不能作为出站节点；只监听本机的入站只能被同一节点上的入站选用
- 出站节点开启了白名单时，会自动放行经它出站的节点；规则之间形成循环（A 经 B、B 又经 A）时无法保存
- 被选作默认去向或分流去向的入站不能直接删除，需先解除；订阅源刷新时也会保留这些节点。出站节点如果随**节点一起被删除、或其所在内核被强制卸载**，原本经它出去的流量会被丢弃（不会改为直连），请重新选择；被引用的入站所在内核**普通卸载会被拒绝**，需先解除引用或确认强制卸载。
- 用户流量统计照常按用户计算
- 保存会重启节点内核，正在经这个节点连接的会断开一下重连。如果你正用这个节点打开面板，保存时连接会中断，面板会在节点恢复后自动确认是否已保存
- 新配置下发或启动失败时（例如分流规则集下载失败导致下发中止、或内核无法按新配置启动），节点会继续使用上一次能运行的配置并显示错误，不会因此掉线

## 节点连接日志

记录「哪些 IP 在什么时候连过这台服务器、连了哪个端口、连了多久」：在节点页打开该节点的连接日志查看。仅管理员可见（记录含真实客户端 IP，普通用户看不到这个入口）。列表列为：状态（连接中／已断开／已中断／连接事件）、客户端 IP、连接端口、入口／入站名、网络／会话类型、连接时间、断开时间、时长；顶部可按客户端 IP 精确过滤，结果分页显示。

**默认全部关闭**：连接日志默认对所有节点关闭，不采集也不显示；由用户在节点页按节点开启——节点开启后，该节点的直连与中转连接都会被采集并显示，采集门控只有这一个节点级开关。面板总开关 `connlog_enabled`（默认开启）仍是全局门：总开关关闭时全部节点的采集随下一次配置推送停下（即使节点已开启）；已入库的历史记录仍可查询、照常按保留期清理。

记录来源分两种：

- **经中转连入**：由整个节点的**入口机**自动采集（真实客户端 IP 与连接的起止都以入口机为准），记到入口节点名下，在入口节点的连接日志中查看，与落地节点是否开启无关，也不需要在落地机上做任何设置。链式隧道的中间跳与落地腿不产生记录。
- **分流目标不产客户端连接记录**：某入站被另一入站选作分流目标（分流规则 `action=SplitProxy`，目标为该入站）时，经它出去的分流腿连接对端是源入站所在机器，不记为客户端连接记录；只有真实客户端直连到入站的连接才会被记录。
- **直连连入**：节点开启连接日志后，新连入的直连连接才会被记录。**仅中转入站**没有直连入口，不产生直连记录；经中转进入的连接由入口机采集、记到入口节点名下，在入口节点的连接日志中查看。

读法与口径：

- **已中断**：连接没能正常收尾（如入口机 agent 重启），断开时间是最后已知时刻、时长留空，不冒充真实断开时间。
- **Xray 内核**的直连入站只能提供连接事件、没有断开事件：状态列显示第四种芯片「连接事件」，时长列恒显「—」，视图内有注记「Xray 仅提供连接事件，无时长」；连接时间与客户端 IP 照常记录。该注记只在当页含「连接事件」行时出现，当页没有这类行时不显示。
- **UDP** 按会话记录，不是逐包精确值。**gost 入口**：一轮无包活动超过约 30 秒视为会话结束，时长精度为会话级（约 30 秒粒度）。**sing-box 入口**（Hysteria2 / TUIC 等直连入站）：会话关闭时刻由 sing-box 内部终结行决定，其空闲窗口尚未钉死——不要按 30 秒预期，真实窗口待后续真机实测确认后补写。
- 记录的时间以**入口机时钟**为准；不记录连接的目标地址。
- 保留期默认 **7 天**（面板配置键 `connlog_retention_days` 可改），且每入站最多保留 5 万行，超期或超量自动清理，日志页脚会显示当前保留天数。入口机采集缓冲溢出丢弃过记录时，页脚会点名「本节点累计丢弃 N 条记录（清空连接行后归零）」——丢弃只丢最旧、不影响新连接记录；该数是节点级累计，连接行被清光后归零。
- 连接日志不进备份（属遥测数据，恢复备份后由 agent 持续上报自然重建近况）。

## 分享与订阅

- 点击入站 → **分享**（电脑上也可以直接点行内的“分享”按钮）：显示通用分享链接和二维码
- **订阅** 页：一个链接包含落地和中转线路，可以建多个、各自选落地与中转范围，也可以分享给别人，见 [订阅](./subscription.md)
- **分享地址**：新建 / 编辑入站时可选客户端连接用的地址——**自动**（节点默认地址）、**节点 IPv4**、**节点 IPv6** 或 **自定义域名 / IP**。分享链接、订阅下发与链式代理的下一跳统一使用该地址；选 IPv4 / IPv6 后节点地址变化会自动跟随；节点没有对应地址族时不能选该档（保存会报错）。自定义地址须是规范主机名或 IP（尾点域名会自动规范化；含下划线、中文域名、回环地址的值不接受）

| 订阅格式 | 适用客户端 | 不包含 |
|----------|------------|--------|
| 自动识别 | 按客户端 UA 返回对应格式 | |
| Clash / Mihomo | Clash Verge、Stash、FlClash | NaïveProxy |
| sing-box | SFA / SFI / SFM | XHTTP |
| Shadowrocket | Shadowrocket | NaïveProxy |
| Loon | Loon | TUIC、gRPC、XHTTP、NaïveProxy、TCP+HTTP 头伪装 |
| Quantumult X | Quantumult X | Hysteria2、TUIC、gRPC、XHTTP、ShadowTLS、NaïveProxy、TCP+HTTP 头伪装 |
| 通用 base64 | v2rayN、NekoBox |  |
| Surge | Surge | VLESS、Reality、gRPC、XHTTP、NaïveProxy、TCP+HTTP 头伪装 |

**导入**的 Snell 节点按格式有口径：sing-box 订阅侧略过 v1–v3（只下发 v4 / v5（按 v4 渲染）/ v6 口径）；Clash 格式下发 v1 / v2 / v3，其中 v1 / v2 强制以 `udp: false` 输出（mihomo 不接受这两个版本的 UDP 开关为真），v4 / v5 不下发（mihomo 收到会整份拒绝）；Stash / Shadowrocket 下发 v1–v4（原样）、v5 按 v4 渲染下发，v6 与负数等异常版本略过不下发。导入的 Snell + ShadowTLS 节点：sing-box 侧经 shadow-tls 转换（detour 双出站）下发，两种存储形态（`shadow-tls` 键形态、Clash YAML 的 `obfs-opts` 形态）同口径；带 shadow-tls / restls / jls 混淆的导入节点在 Clash 格式不下发（mihomo 无此混淆模式、收到会整份拒绝）；v3 带 http / tls 混淆的导入节点 Clash 照常下发、sing-box 侧不下发（sing-box 的 Snell 客户端没有混淆模式可表达）。

NaïveProxy 的 sing-box 出站需要 sing-box 1.13 及以上：节点 sing-box 低于 1.13 时，以 NaïveProxy 节点为链式落地（默认去向或分流目标）在保存、下发和更换内核版本时会被点名拒绝，把节点 sing-box 升到 1.13 及以上即可；订阅侧同理，sing-box 客户端低于 1.13（按拉取请求的 UA 判定）时不下发 NaïveProxy 节点、其余节点照常下发。自建 NaïveProxy 入站本身不受此下限影响。

VLESS 加密（ENC）入站不在上表的协议排除之列，但只有 Clash / Mihomo、Stash 与通用 base64 输出会携带它的完整 `encryption` 参数，其余格式（sing-box、Shadowrocket、Loon、Quantumult X、Surge）直接略过这类入站。

## 节点展示分组

节点多了可以在节点页按组分段浏览（纯展示，不参与订阅、转发、选线）：一节点至多一个分组标签，卡片和列表两种视图都按组分段，段标题是「组名 + 台数」，未分组的节点沉在最后一段；搜索和筛选先过滤、再分段，没有节点的组不出现空段；所有节点都没有分组时页面与未分组时完全一样，不出段标题。分组只是展示标签，节点上的 agent 也不感知它。

- **建组**：工具栏 **新建分组**，输入组名即建组（组名会登记进分组名单；空组也存在，只是不在页面出段，归入节点后自动出现）。
- **归组**：进入 **多选** 后用 **移入分组** 把节点批量移入/移出；编辑节点时也可以在 **展示分组** 下拉里单台选组。
- **管理**：工具栏 **分组管理** 弹窗里可以拖拽排序、改名（成员自动跟随，改名级联到组内全部节点）和删组（成员回落未分组，不删节点）；组顺序按组名存面板设置，名单之外的新组按名称排序、排在已定顺序之后。
- **备份**：分组标签与组顺序随节点一起进备份 / 恢复。

### 折叠分组段

- **折叠/展开一段**：点击段标题行（组名左侧的箭头图标）即可折叠或展开该段，卡片、列表两视图口径一致，未分组段同样可以折叠。折叠后只剩段标题行，组名和台数照常显示；台数与展开时完全一致（当前搜索/筛选结果内该段的节点数），折叠不改变任何计数。
- **全部折叠/全部展开**：工具栏 **全部折叠** 一次折叠当前所有段，**全部展开** 一次展开全部。
- **持久化**：折叠状态按组名存面板设置（配置键 `node_display_group_collapsed`，值是 JSON 数组，未分组段记为空字符串 `""`），和组顺序（`node_display_group_order`）同一通道保存，跟随面板与备份——刷新页面、换浏览器或换设备打开都保持，不存浏览器本地。分组改名后折叠状态自动跟随新名，删组后对应记录自动摘除；折叠名单里已不存在的组名无副作用，日后同名组重建时会恢复折叠。
- **与多选的关系**：折叠只是不渲染段内节点，不改变选择状态——在多选模式下先勾选再折叠，该段已选节点仍计入顶部已选计数，批量升级/删除/移入分组照常作用于它们；**全选** 的范围也不受折叠影响（仍是当前显示列表全集）。

## 批量操作

入站多了不好管理时，点列表上方的 **多选**：点卡片勾选，**全选** 会选中当前列表里显示的全部入站（可以先用搜索或节点筛选缩小范围），然后可以批量 **启用**、**停用** 或 **删除**。每个受影响的内核只下发一次配置。

## 节点延迟

面板可以让每个节点定时向一组测试点做 TCP 延迟探测，在节点卡片和列表里直接看到各线路的延迟。

### 配置测试点

**网站配置 → 延迟测试点**：添加测试点（名称、地址、端口），最多 30 个；可以把最多 3 个固定显示在节点卡片上（其余的点进下拉查看）。仅管理员可配置。

测试点改名后，已选择该测试点的节点会自动跟随新名称（只在地址不变时成立：改名靠地址认出是同一点）；改名同时改了地址时，自选会失效、节点回退全局默认；保存回执会点名提示哪些节点的自选已失效并回落全局默认（逐项点名节点与测试点，最多列 5 项、其余以「等 N 项」汇总），保存后以 ⚠️ 提示原文透出，不会静默处理——想保住自选，须先改名、再另改地址（分两次保存），或改后重新勾选。删除测试点后，相关节点回退到全局默认。

### 查看延迟

**节点** 页卡片视图和列表视图都有延迟显示：每个测试点一个数值，颜色按延迟分档：

| 延迟 | 颜色 |
|------|------|
| < 100ms | 绿 |
| 100–300ms，或有丢包 | 橙 |
| ≥ 300ms，或丢包 ≥ 50%，或不可达 | 红 |

### 节点自选测试点

默认所有节点测全局启用的测试点。想让某个节点只测指定的点：节点操作菜单 → **测试点** → 切到自选并勾选，保存后会立即重测该节点。注意两种「空选」的区别：未启用自选时跟随全局默认；启用自选但不勾任何点，表示该节点**不做**延迟探测。

UDP 族目标（udp / kcp / quic）没有与 TCP 对等的延迟测量通道，口径不同、不要按 TCP 的预期读：隧道质量探测与中转延迟面不测 UDP 段、直接标「未测」；只有手动诊断的链路段会下发 `UdpPing`，它只尝试建立 UDP 会话、结果恒为「未验证」，不产生延迟数值，也不占用 TCP 探测的槽位。看到 UDP 段显示未测 / 未验证是当前实现的正常口径，不是节点故障。

## 节点协议开关

节点编辑表单里有 **HTTP / TLS / SOCKS** 三个协议开关。它们是**屏蔽开关**，不是监听开关：把某类开关**打开**后，Agent 会对经隧道转发进来的每条**新建 TCP 连接**先嗅探首字节，命中该类协议（HTTP 请求、TLS 握手、SOCKS 握手）就**直接关闭这条连接**；开关关闭则不嗅探、正常放行。作用面就是隧道转发本身（已建立的连接不追溯，改动从下一条新连接起算）；UDP 连接不做协议嗅探、恒放行。保存时面板经 `SetProtocol` 命令下发、Agent 立即应用并落盘；节点每次握手时把三开关的当前状态随节点信息一并自报，面板以自报值为准显示（离线时改不了、会被拒绝而不是静默丢失）。

::: warning 别按字面理解反了
打开开关＝开始屏蔽该协议的转发流量，不是「启用该协议的服务」；反过来，以为关掉开关只是关了个没用的监听，实际是解除了屏蔽、放行该协议。改完后自检：开关打开时经该节点转发一条对应协议的连接应立即断开，关闭时应正常通过。
:::

## 本月流量（网卡）

**节点** 页卡片 / 列表与实时统计区显示每个节点的 **本月流量（网卡）**（上行 / 下行分列）：

- 口径是**整台机器网卡的流量**（agent 上报网卡累计计数的差分），包含该机的一切流量，不只是经面板转发的业务；
- 按查看者浏览器时区的自然月统计（每月 1 日起算），逐小时落账；
- 这是机器用量的参考数字，与 [订阅流量统计](./subscription.md#流量统计)（按订阅凭据计）和转发计费（按隧道倍率折算）的口径都不同，**不能互相换算、不能作计费依据**；
- 网卡增删不会重复计入；agent 或整机重启后的第一个统计窗口可能少计一小段，属已知口径。

## 节点调优

优化节点主机的网络栈，适合跨境、高延迟线路。调优由四个「面」组成，每面独立应用、独立报告状态；窗口顶部同时显示当前拥塞控制算法与默认队列算法。注意一处键集重叠：生产级内核调优面的键集包含拥塞算法 BBR 与 fq 队列，应用该面会同时激活 BBR 面（两面共用同一组运行时值），其余各面之间互不依赖。

操作路径：**节点** 页 → 某节点的操作菜单 → **调优**（仅 agent 模式节点显示，nftables 模式节点没有此入口）。

| 面 | 作用 | 落地方式 |
|----|------|---------|
| IPv4 优先解析 | 让域名解析优先返回 IPv4 地址，避开 IPv6 绕路造成的握手卡顿 | `/etc/gai.conf` 写入优先规则 |
| BBR + FQ | 拥塞控制换 BBR、默认队列换 fq，降低跨境丢包影响（需内核 4.9+） | `/etc/sysctl.d/10-bbr.conf` |
| 生产级内核调优 | 缓冲区按机器总内存的 5% 定尺寸，连接队列与文件句柄拉高，开启 Fast Open、MTU 探测、端口范围扩容等 | `/etc/sysctl.d/99-network-performance.conf`、`/etc/security/limits.d/99-network-performance.conf`，并对出站 TCP 做 MSS 钳制 |
| 网卡多队列均衡 | RPS 把收包软中断平摊到全部 CPU 核心，消除单核瓶颈（跳过 lo/docker/veth 等虚拟网卡） | 网卡队列 sysfs 设置，并把网卡 RX/TX 环形缓冲推到各自最大值；RPS 经 `flmx-tuning-rps.service` 持久化、开机自动重放，不是只在运行时生效 |

- 四面可独立应用：只想换 BBR 可只点那一面；已激活的面可「重新应用」刷新参数。例外：应用生产级内核调优面会同时激活 BBR 面（其键集包含 BBR 与 fq），不是完全独立
- 参数尺寸由 Agent 按机器总内存自动定，不再需要填写带宽与延迟；旧版的自动调优（iperf3 测速）、深度优化（整形拐点扫描）、带宽/延迟手填与分组勾选已全部下线
- **一键回退默认**：删除上述调优文件，移除 MSS 钳制规则并清零 RPS 设置；sysctl 运行时值优先按应用前自动保存的快照恢复成你原来的值（原本用 fq_codel 就恢复 fq_codel，不是无条件写死回默认），只有没有可用快照时才兜底切回 cubic / pfifo_fast，未能回退的键会在回退结果里点名；gai.conf 会恢复到应用前的备份
- 不支持的内核参数只会 warning 跳过，不会中断整个应用过程
- 节点 Agent 版本过旧（不支持新版调优）时会提示先升级节点 Agent

### 线路探针

与调优四面并列的只读测量，不改任何参数：面板下发探针后，Agent 采样节点当前已建立 TCP 连接的内核 RTT（中位数），并可向参考主机发起一轮 10 次顺序 TCP 连接采样、以中位数作为面板 RTT 参考值（同时给出最小/P95/最大与丢包率等分布统计）。窗口呈现延迟；节点暂无可测连接时提示延迟不可用。参考主机留空时自动使用面板地址，且只接受公网地址（面板与 Agent 双重校验）。原先基于下载测速的带宽建议已随新调优下线。

## 定时重启 agent 服务

给节点加一道保险丝：按设定节奏自动重启节点上的 **agent 服务**（`flmx_agent`），把长跑攒积的连接态清零。**重启的只是 agent 服务，不是整机重启**；重启瞬间转发会短暂中断，服务恢复后自动重连面板。

操作路径：**节点** 页 → 某节点的操作菜单 → **定时重启**（仅本面板直管的 agent 模式节点有此入口；nftables 节点没有 agent 服务、不支持）。

弹窗里先选模式，两种二选一：

| 字段 | 填法 |
|------|------|
| 开关 | 默认**关**。打开后才生效 |
| 模式 | **每天定时**（默认）或**按间隔**，见下两行各自的字段 |
| 重启时刻（每天定时） | 24 小时制 `HH:MM`，按**节点本机时间**每天触发（如 `04:00`） |
| 重启间隔（分钟）（按间隔） | `15–10080` 的整数，每隔该分钟数触发一次（如每小时填 `60`、每 2 小时填 `120`；弹窗有 30 分钟 / 1 小时 / 2 小时 / 6 小时 / 12 小时快捷档，也可直接填自定义分钟数）。适合小内存节点拿它当攒积保险丝，不必等到每天定点 |
| 随机抖动（分钟） | `0–720` 的整数，两模式通用。实际触发时刻在名义时刻之后的 0 到该分钟数内随机，多台节点设同一节奏时用它错开，避免同时重启 |

生效方式与注意：

- 计时器保存在节点本机（systemd timer），**面板离线或暂时连不上时照常执行**；关闭开关会把节点上的计时器删除
- 按间隔模式的计时从节点开机 / 计时器启用起算：**首次触发在一个间隔之后**（不是保存后立即重启）；节点关机期间错过的拍不会在开机后补成一串，开机后重新按间隔节奏走
- 机器重启后计时器自动恢复（随 systemd 启用状态持久化），不需要重新设置；改模式或改间隔后保存即换写节点上的计时器，不会并存两个
- **仅 systemd 环境生效**：计时器靠节点本机的 systemd timer 落地；Alpine / OpenRC 与容器形态的节点没有 systemd，在这些节点上开启会下发失败、不会真正生效，不要把这道保险丝算在它们头上
- 节点离线时改设置：先存面板，节点重连时自动补发，不需要重新设置
- 节点 agent 版本过旧（不认识此设置）时会提示先升级节点 Agent；设置已存面板，升级后自动生效
- 这是保险丝不是治本手段：内存/连接态根治在转发层本身，定时重启只作兜底
- 自检（仅 systemd 节点）：保存后在节点上执行 `systemctl list-timers flmx-agent-restart.timer`，能看到下一次触发时间即已生效；关闭后该命令应无结果

## 一键设置 Swap

给节点补一道内存兜底：由面板下发节点 agent 在节点机上管理 `/swapfile`（新建、调大小、写入 fstab），适合存量小内存节点——装机时没建 swap、或当初建的大小不够用，不用再登录节点机敲命令。

操作路径：**节点** 页 → 某节点的操作菜单 → **设置 Swap**（列表视图），或卡片视图操作区里的 **Swap** 按钮。入口只对非 nftables 节点显示（nftables 节点没有 agent 服务）；节点离线时入口禁用（现状与执行都要经在线的 agent）；两个接口均为管理员专属。

打开弹窗会先向节点拉取现状，四格读法：

| 格 | 内容 |
|------|------|
| 当前 Swap | 全机 swap 总量与已用（全机口径，含非面板管理的条目） |
| 内存总量 | 节点整机内存 |
| 磁盘可用 | `/swapfile` 所在磁盘的剩余空间 |
| 现有条目 | 逐条列出在用的 swap（名称与大小） |

现状下方会按机器实况给出三种形态之一：

- **已有面板管理的 /swapfile**：执行将把它调整为所选大小（总量随之变化），并同步更新 fstab
- **现有 swap 非面板管理**（如面板之外自建的分区 swap）：面板不会动它，执行将另建 `/swapfile`、总量叠加
- **当前没有 swap**：执行将新建 `/swapfile` 并写入 fstab（重启不丢）

现状拉取失败时弹窗只显示常驻错误与「重试」，不提供执行——无法确认节点现状时，不在未知状态下改动节点的 swap。

**选择大小**：预设 1 / 2 / 4 / 8 GB（打开默认选 2 GB），或自定义 **1–32 的整数 GB**；越界在弹窗内即时拦下，面板与 agent 执行时还会各复判一次。

**空间口径（以 agent 复判为准）**：可用空间按「磁盘剩余＋现有 `/swapfile` 文件占量」计（调大小时旧文件占量在重建时释放），须 ≥ 目标大小再另留 **256MB** 预留才放行；不足时回执原文写明需要的总量、当前可用与各分量数值。弹窗会按现状先行拦截明显不足的选项并提示还差多少，最终以 agent 回执为准。

**swapoff 风险拒绝**：调大小须先关闭现有 `/swapfile`。若它当前已用量**大于机器可用内存**，agent 会拒绝执行并在回执里写明两个数值——此时 swapoff 会把换出页全部压回内存，可能把小内存机当场压死；请先降低内存占用、或在低峰期再试，拒绝时机器状态不变。可用内存读不到且现有 swap 已有用量时，同样按拒绝处理。

**只管 /swapfile**：既存的分区 swap、别的文件 swap 等非面板管理条目只在现状里报告，永不修改或删除；写 fstab 时只收敛 `/swapfile` 一行（恒为恰好一条 `/swapfile none swap sw 0 0`），其他条目与注释行逐字保留。

**执行与回执**：点「确认执行」后按钮锁定防重复提交；大文件在慢盘上可能要数分钟，请等回执出现再关窗（关窗后本次回执不再展示）。成功后弹窗展示执行前后总量/已用对照（before → after）；回执若带非致命提示（如旧 swap 备份文件删除失败），会逐条以 ⚠️ 提示透出。中途任一步失败，agent 会删除半成品、尽量恢复执行前的旧文件与旧 swap，错误文案常驻弹窗、写明失败步骤与当前实际状态。有一个失败形态要特别注意：**swap 已按所选大小启用、但写入 /etc/fstab 失败**时，回执会明确报错并写明「新 Swap 正在生效，但重启后不会自动挂载」，同时给出要人工补进 `/etc/fstab` 的那一行原文——见到这条要按提示补行，否则重启后 swap 消失。

**其他拒绝形态**：节点 agent 版本过旧（不认识此功能）时回执为「节点 agent 版本过旧，不支持一键设置 Swap，请先升级节点 Agent」，先升级 agent 再用；agent 运行在容器中时回执会点名其无法管理宿主机的 Swap。

**与装机自动 swap 的分工**：安装/更新脚本的自动防线只在装机或脚本更新时触发，且只对**内存 ≤512MiB 且当前完全没有 swap** 的机器自动建 1G（见 [安装](./install.md) 的「小内存机自动建 swap（装机防线）」节）；经面板内升级上来的存量节点不会被补建。一键设置 Swap 是面板侧随时可用的手动入口：任何时候可建、可在 1–32G 内调大小。脚本自动建的 `/swapfile` 在弹窗里即呈现为「面板管理」形态，可直接接着调大小。

**完成后自检**：弹窗现状里「当前 Swap」总量应等于所选大小（另有非托管 swap 时为所选大小＋其大小）；或登录节点机执行 `swapon --show; grep '/swapfile' /etc/fstab`，应见 `/swapfile` 在启用列表中、fstab 里恰有一条 `/swapfile` 行。

## 备份

在 **网站配置 → 数据备份与恢复** 里勾选 **内核与入站**，会导出节点上的内核、所有入站（包括导入的节点）、中转线路和流量统计基准。所有订阅（包括分享出去的）也包含在内。恢复后面板会把内核配置重新推到在线的节点，离线的节点重连时自动补上。注意配置键的过滤口径：导出时**未分类的配置键**（例如经 API 写过的自定义键）按默认敏感口径被静默剔除、不进备份文件，导入方向则保留未分类键——自定义键不要指望随备份迁移。

本地导入的取消口径：提交导入后，面板先生成一份导入前自动备份快照；快照完成、开始写入之前关闭页面或断开网络，导入整单取消、不产生任何改动；一旦开始写入，导入会在服务端整单跑完，关闭页面或断网不影响导入完成、也无法再取消，请等待导入完成后再核对结果。同一时刻只允许一单备份导入，导入进行中再次提交会被拒绝并提示。

注意：备份同样包含节点 SSH 配置，敏感程度与面板数据库相当，备份文件请按凭据文件同等保管、不要随意外发。3.0.9 之前导出的备份不包含这部分，升级后请重新导出一次。（注：3.0.x 是本项目上游的旧版本线；现行版本导出的备份均包含这部分，这句只针对从旧版本线带过来的存量备份。）

## Pending Delete 管理接口（管理员）

当节点离线时删除转发，系统会将其标记为 pending-delete（status=2），由后台任务按退避策略（1m/5m/30m/2h，上限 24h）自动重试清理。以下接口用于可观测性：

### POST /api/v1/node/nftables/pending-deletes

列出所有待清理的转发。

- **权限**：仅管理员（roleID=0）
- **请求**：POST，无参数（需 Authorization 头带 JWT）
- **响应**：`{code, msg, data: [{forwardId, forwardName, nodeId, nodeName, retryCount, nextRetryAt, lastError, createdAt}], ts}`（字段名为 camelCase）
- **用途**：退避耗尽转人工后，管理员在此查看哪些转发需要手动处理

### 相关行为

- pending 行不会出现在转发列表中（`ListForwards` 恒过滤 status=2），只能通过上面的 pending-deletes 接口查看
- 配额释放、恢复、批量操作均不会复活 pending 行
- 隧道删除时，pending 行合并进同节点清理批次
- 切换节点转发模式（agent ↔ nftables）时，若该节点是已有转发隧道的入口节点会被拒绝：切换不迁移数据面服务，须先删除或移出该隧道的转发（或编辑隧道去掉本节点入口）后再切换

## 删除节点

删除确认窗里有一个默认勾选的 **同时卸载服务器上的 agent**。勾不勾选，删掉的范围不同，先分清。

**与升级类操作的在途互斥（先看这一条）**：删除与节点升级、回退、卸载共用同一份在途登记，同一节点同一时刻只允许一个这类操作在途。节点有升级 / 回退正在进行时发起删除，会被**整体拒绝**、回执点名在途的操作（形如「该节点已有升级操作正在进行，请等待其完成后再试」）——这是预期互斥、不是故障，等在途操作完成后再删即可，不要反复重试。反过来，删除（尤其连带卸载）进行期间，该节点的升级、回退也会按同一口径被拒并点名。批量删除时逐节点判定：被拒的节点在批量回执里逐条点名，其余节点照常删除。

**面板侧清理（不论勾选与否）**：面板会先尝试通知节点清理它上面的转发服务和 nft 规则，然后再删除面板里的节点记录。但这个清理是**尽力而为、不保证成功**：

- 节点在删除时离线或不可达，清理指令发不到节点，删除仍会继续（否则离线节点永远删不掉）
- 清理失败只会记进面板日志，不会阻止删除
- 删除节点时，如果其他节点上的入站正把本节点入站选作默认去向或分流去向，确认弹窗与删除响应会点名这些将被打断的跨节点引用（回传清单）；请先解除引用，或确认接受这些入站的出站流量被丢弃后再删除

**勾选「同时卸载 agent」（默认）**：面板会让节点上的 agent 自卸载——停掉内核进程、删除自建的 nft 表、恢复调优改过的系统参数，并删除安装目录（脚本形态）或清空数据目录（容器形态，容器本体会留一个卸载标记空转，请之后手动删掉容器）。删除回执会点名卸载结果是哪一种：

- **正在卸载**：节点在线且 agent 已确认，面板提示 agent 正在卸载
- **下次连接时自动卸载**：节点离线或未确认时先登记（面板提示「已登记：它下次连接面板时将自动卸载 agent」），节点下次连接面板时会被拦截并自动执行卸载，不必再回面板操作。登记没有时间过期：发出登记后 10 分钟内未收到 agent 的终局上报，登记会被置为「未确认」并保留；终局上报失败同样保留登记与节点记录——两种情况都不会自动过期消失，等管理员重试卸载，或不带卸载地强制删除节点记录。旧的「180 天保留期」口径已随登记表迁移失效，不要再按它判断登记是否还在。
- **版本过旧、需手动卸载**：节点上的 agent 版本过旧、没有自卸载能力，回执会点名提示，需要登录节点机手动清理
- **卸载失败 / 结果未确认**：agent 终局上报失败，或 10 分钟内未收到终局上报，登记与节点记录都会保留、节点不会自动消失；节点列表里会透出失败或未确认状态，等管理员重试卸载或强制删除记录

节点列表与卡片上的卸载状态芯片共有五态：**卸载已下发**、**卸载执行中**、**卸载已完成**、**卸载失败**、**卸载结果未确认**；其中卸载失败与卸载结果未确认两态会常驻显示具体原因。

> 只想把这台服务器**移到另一个面板**管理时，请**取消勾选**：否则 agent 自卸载会把自己删掉，迁过去还得重装。

**不勾选时**：只删面板记录和上面的转发清理，agent 本体、内核进程与配置文件都留在节点机上继续运行，之后想清理要自己登录节点机处理。

**在节点机上用安装脚本卸载（脚本形态）**：登录节点机重新下载安装脚本、选「3. 卸载」，清理范围与面板自卸载一致：停掉并禁用 agent 服务；赶在删安装目录之前按调优备份与面③ 快照恢复调优前的系统参数（sysctl 原值写回、整形前队列回放）；删除调优留在宿主机上的文件——第二代四面文件：内核参数 `/etc/sysctl.d/99-network-performance.conf`、limits `/etc/security/limits.d/99-network-performance.conf`、BBR `/etc/sysctl.d/10-bbr.conf`、RPS 助手脚本 `/usr/local/bin/flmx-tuning-rps.sh` 与其持久化服务 `flmx-tuning-rps.service`、面③ 调优前 sysctl 快照 `/etc/security/flmx-tuning-kernel-sysctls.json`（先按快照写回原值再删除；快照缺失时回退三项标题默认值——拥塞控制 cubic、默认队列 pfifo_fast、rps_sock_flow_entries 0，并在卸载输出中点名其余未能回退的键）；并按备份还原 `/etc/gai.conf` 后删除其备份 `/etc/gai.conf.bak`、删除 MSS 钳制 iptables 规则（非文件）；第一代残留名（`/etc/sysctl.d/99-flmx-tuning.conf`、`/etc/modules-load.d/flmx-bbr.conf`、队列整形服务 `flmx-tuning-qdisc.service`）也一并清理；删除 agent 自建的 nft 表（`flmx_kernel`、`flvx_kernel`、`flmx_hop_probe`）；最后删除服务文件与安装目录。**共存例外**：其中两项与旧谱系 agent 同名共用——改名前 legacy 名的调优文件 `/etc/sysctl.d/99-flvx-tuning.conf` 与 nft 表 `flvx_kernel`；若卸载时仍检测到旧式 gost agent 足迹，这两项会被**跳过不删**、在卸载输出中逐项点名并给出人工删除法（归属不明时不误删他方资源），其余清理照常执行；无旧式足迹时两项照常删除。卸载输出会逐项列明每一项的清理结果，未能完成的项会单独标出并给出人工清理法。两条路径的差别只在触发方式与对象：脚本卸载不会删面板里的节点记录（删完后请再回面板删除该节点，或先在面板删节点时取消勾选、再到节点机跑脚本卸载），且只适用于脚本形态节点。例外：若整形前的队列备份已丢失，两条路径都会标明队列整形无法恢复、其余清理照常执行——sysctl 原值仍按调优备份写回、宿主调优文件照常删除；面板自卸载时这一情况会在删除回执里点名（不再是无说明的「正在卸载」），残留的运行时整形在宿主机重启后随 tc 状态自动消散。

所以：**删除节点成功，不等于节点机上的运行时已经清干净**（不勾选、或勾选但回执点名版本过旧时尤其如此）。推荐顺序：

1. 优先在节点还在线时删除，并保持默认勾选，让自卸载当场执行、回执为「正在卸载」
2. 离线删除且保持勾选的，等节点下次上线即自动卸载，无需再管
3. 只有不勾选、或回执点名 agent 版本过旧时，才需要登录节点机手动清理：重新下载安装脚本选「3. 卸载」，按上面脚本卸载的范围清干净——不要只停服务、只删安装目录，调优宿主文件与 nft 表残留在宿主机上会开机重放、长期存续

## 出站 IP 策略

新建 / 编辑入站的**高级选项**，或入站的**出站**里，可设置“出站 IP 策略”：

- **自动（IPv4 / IPv6）**：沿用内核和系统的默认选择。
- **仅 IPv4 出站**：保持入站监听地址不变，域名只解析 IPv4；直接请求 IPv6 目标会被拒绝，不会回退到 IPv6。这样客户端仍可通过 IPv6 连到节点，而本机的业务出站只走 IPv4。
- **仅 IPv6 出站**：保持入站监听地址不变，域名只解析 IPv6；直接请求 IPv4 目标会被拒绝，不会回退到 IPv4。节点必须具备可用的 IPv6 地址和路由，只支持 IPv4 的网站无法访问。
- **优先 IPv4（失败回退 IPv6）**：保留双栈解析，TCP 先尝试 IPv4；连接失败或约 250ms 内尚未连通时启动 IPv6 备用尝试，采用先成功的连接。域名没有 A 记录时直接尝试 IPv6。
- **优先 IPv6（失败回退 IPv4）**：与上面相反，TCP 先尝试 IPv6，失败或迟迟未连通时尝试 IPv4；域名没有 AAAA 记录时直接尝试 IPv4。

优先模式需要 Xray 25.6.8+ 或 sing-box 1.12+；仅 IPv4 / 仅 IPv6 在 sing-box 上同样需要 1.12+。UDP 按解析结果优先选择地址；因为 UDP 没有连接握手，远端静默不回包无法可靠判定故障，不会自动把同一数据包重放到另一种 IP。

支持 Xray、sing-box 1.12 及以上。策略按入站保存，编辑、重新下发和重启后仍生效；把节点内核降级到不支持已保存策略的版本会被拒绝。

指定出站 IP 策略时，高级 JSON 不能覆盖 `tag` 或 `detour`，以免绕过按入站生效的策略；存在冲突会提示并拒绝保存。

直连分流和用户流量统计同样遵循策略。链式 / 代理分流连接下一跳时也遵循所选 IP 策略：下一跳是与策略冲突的字面 IP 时保存会被拒绝（域名放行，由内核按同一策略解析）。网站最终看到的出口由下一跳节点决定，需要在最终落地上同样设置策略。
