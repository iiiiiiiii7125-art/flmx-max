# 流量转发与管理

面板保留了原有的转发面板功能：多用户、端口转发和隧道转发、配额与限速。

## 仪表盘 (Dashboard)
登录系统后首先看到的是仪表盘，这里展示了系统的整体运行状态，包括：
- 在线节点数量
- 用户总数
- 流量统计信息

## 节点管理 (Node)
节点是实际承载流量转发的服务器。
- **添加节点**: 点击“添加”，获取密钥用于节点端安装。
- **管理**: 可以查看节点在线状态、版本信息，以及对节点进行编辑或删除。

## 用户管理 (User)
管理员可以创建和管理普通用户。
- **创建用户**: 设置用户名、密码、流量配额等。
- **用户组**: 可以将用户分配到不同的组 (Group)，便于统一管理权限或策略。

## 转发管理 (Forward)
这是核心功能区，用于设置端口转发规则。
- **端口转发**: 将节点服务器的某个端口流量转发到目标地址。
    - **协议**: 支持 TCP / UDP。
    - **入口**: 选择入口节点和监听端口。
    - **出口**: 设置目标 IP 和端口。
- **隧道转发**: 流量经隧道在节点之间穿透，包括“前置 → IX → 落地”多跳线路，见 [对接中转](./relay.md)。

### 端口占用与复用口径

- 端口冲突只看**同一节点上的同一端口**：同一端口可以同时用在不同节点上，互不影响。
- 同一节点上，转发、隧道链路与入站共用同一端口空间，分配时统一做占用校验。
- 自定义入口端口（inPort）必须是 1–65535，且落在该节点的端口范围内，否则会被拒绝。
- 多入口转发不能自定义监听 IP（inIp）；编辑转发时不改监听 IP 会保留原 IP，切换隧道时才重置。

### 删除与端口回收

- gost 模式的转发删除后，节点上的监听服务随即移除，端口释放。
- nftables 模式的转发删除走“先标记待删除（pending-delete）→ 后台对账确认节点侧规则已移除 → 删除记录”：节点离线时删除会进入 pending-delete，由后台任务按 1m / 5m / 30m / 2h 退避自动重试，上限 24h 后转人工处理；等待期间该端口仍视为占用，不会分配给新转发。管理员可通过节点页的 Pending Delete 管理接口查看待清理项，见 [节点管理](./nodes.md)。

## 限制与策略 (Limit)
- **限速**: 可以对指定用户或指定隧道进行带宽限制，防止资源滥用。
- **计费模式**: 支持配置流量计算方式（单向或双向），适合运营场景。转发流量按入、出两个方向分别统计，配额扣减按计费口径累计。
