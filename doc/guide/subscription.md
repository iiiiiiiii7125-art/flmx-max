# 订阅

**订阅** 页管理所有订阅链接。思路和 Sub-Store 一样：**来源 → 处理 → 输出**。每个订阅选一批落地，按需过滤、改名，客户端拿到的格式按 UA 自动识别（也可以复制指定格式的链接）。

升级前的订阅链接会变成这里的“我的订阅”，链接不变；原来的订阅设置和共享用户也会自动迁移过来。

## 订阅与凭据

所有订阅在同一个列表里，靠名称区分（例如“我的手机”“小明”）。

- 新建的订阅都有自己的 UUID / 密码，和你的凭据同时写进节点配置，互不影响
- 可以设到期日期（到期当天 23:59 后断开）和流量上限，留空就是不限；停用、到期或流量用完后，面板会把它的凭据从节点上删掉

编辑时“处理”和“链式代理”默认收起（已设置的会展开），标题旁显示已开启的项目。

## 导入到客户端

点订阅打开详情，按客户端选择：**点客户端直接唤起 App 导入**，右侧按钮复制该格式的链接。也可以复制上面的通用链接，客户端按 UA 自动拿到对应格式。

| 客户端 | 格式 | 一键导入 | 链式代理 |
|--------|------|----------|----------|
| Clash（Clash Verge、Mihomo Party、FlClash 等） | Clash / Mihomo 配置 | `clash://` | ✓ |
| sing-box（SFA / SFI / SFM） | sing-box 配置 | `sing-box://` | ✓ |
| Shadowrocket | Clash 节点列表 | `shadowrocket://` | ✓（每个中转各生成一个“落地（经 中转）”节点） |
| Loon | Loon 节点 | `loon://` | ✗ |
| Quantumult X | QX 节点 | `quantumult-x://` | ✗ |
| Surge | Surge 配置 | `surge://` | ✓ |
| Stash | Stash 配置（Clash 档案，规则集为 YAML） | `stash://` | ✓ |
| 通用 | Base64 分享链接（v2rayN、NekoBox 等） | 仅复制 | ✗ |

- 客户端不支持的协议会自动略过，例如 Loon 没有 TUIC，Quantumult X 没有 Hysteria2 / TUIC，Surge 没有 VLESS
- Loon 和 Quantumult X 的节点格式没有前置代理参数，订阅里的落地节点是直连
- 指定格式的链接：在订阅链接后加 `?format=clash`（或 `singbox`、`shadowrocket`、`loon`、`qx`、`surge`、`stash`、`base64`）
- VLESS 加密（ENC）入站只出现在 Clash / Stash / 通用 base64 输出里（携带完整 `encryption` 参数），其他格式会略过这类入站
- Snell 入站的下发按客户端区分：Clash / Stash / Shadowrocket 按 v4 口径下发（v4 / v5 入站可下发，v6 入站不下发，客户端不支持 v6）；sing-box 需要 1.14 以上版本、按拉取请求的 UA 判定下发——与是否用 `?format=singbox` 指定格式无关，用浏览器等普通工具拉取（UA 不带 sing-box 版本）时不含 Snell 属正常现象；Surge 原生支持；Loon、Quantumult X、通用 base64 不下发 Snell

## 来源

- **全部落地**：包括以后新增的落地，不用再回来勾选
- **指定落地**：只勾选需要的，分“自建”“导入”和“订阅源”三组。订阅源按整个源勾选，以后更新进来的节点会自动跟上；只要其中一部分可以用下面的过滤

落地的中转线路会跟着它一起出现在订阅里。

## 订阅源

在 **落地 → 订阅源** 添加机场或别人的订阅链接，相当于 Sub-Store 的远程订阅。也可以在 **落地 → 导入** 里粘贴订阅地址，打开 **定时同步**（默认打开）就会存成订阅源；关掉则只导入一次：

- 添加后立即拉取一次，节点出现在 **落地** 页“订阅源 · 名称”分组里，可以和其他导入节点一样检测、接中转、放进订阅
- **自动更新**：手动 / 6 小时 / 12 小时 / 每天。也可以点卡片右边的按钮立即更新。面板每 10 分钟检查一次到期的订阅源，实际同步时刻最迟可能比设定间隔晚约 10 分钟
- 更新时按 **名称** 对上已有节点（名称变了再按地址对）：地址变了就跟着改，挂在上面的中转也会改到新地址；订阅里没有了就删除，但挂着中转的会保留，免得中转断掉
- 拉取失败或返回空内容时保留现有节点，卡片上显示错误
- 机场返回的流量和到期信息（`Subscription-Userinfo`）会显示在卡片上
- **上传文件**：拿不到订阅链接时，可以给订阅源直接上传订阅文件（Base64、Clash / Mihomo、sing-box 格式均可，上限 5MB）；文件源不自动更新，要更新时在卡片上点「重新上传」
- **用途**：订阅源可以标成 **中转** 或 **落地**（默认普通）。新建订阅时会自动带入：标了中转的源整源放进链式代理的中转侧、标了落地的整源作落地；在订阅里随时可改
- **新节点设为只通过我的转发访问**：新加进来的节点只用来接中转，不直接进订阅
- 删除订阅源时可以选连同节点一起删除，或只删订阅源、节点留下变成普通的导入节点

典型用法：订阅选“指定落地”，勾上自己的落地和机场订阅源，再用“处理”过滤地区、加国旗、排序，一个链接全搞定。

## 处理

按固定顺序执行：**过滤 → 改名 → 国旗 → 去重 → 前缀 → 排序**，最后输出时可以按地区分组。（去重键只含地址/端口/协议，不含名称，所以去重在加前缀之前做不影响结果。）

| 步骤 | 说明 |
|------|------|
| 线路 | 全部 / 只要中转 / 只要直连 |
| 地区 | 只保留选中的地区；“其他”是名称里认不出地区的节点 |
| 协议 | 只保留选中的协议 |
| 名称包含 / 排除 | 多个关键词用 `\|` 分隔（不区分大小写），或用 `/正则/` |
| 改名规则 | 每行一条 `要替换的 => 替换成`，右边留空就是删除，`/.../` 是正则 |
| 自动加国旗 | 按名称识别地区，在前面加国旗；已经有国旗的不重复加 |
| 名称前缀 | 给所有节点加同一个前缀 |
| 去重 | 地址、端口、协议都相同的只保留第一个 |
| 排序 | 面板顺序，或按名称（`02` 排在 `10` 前面） |
| 按地区分组 | Clash / sing-box / Surge 里每个地区一个自动测速组，列在“节点选择”最前面。这是显式开关：开启后即使订阅里只有一个地区，也会生成该地区的分组标题。它与按节点划分的分组标题是两回事——节点分组标题只在入站分布于多个节点分组时才显示 |

例如导入的节点叫 `花云|香港🇭🇰|1.0x|01`，改名规则：

```
花云| =>
/\|[0-9.]+x/ =>
| => -
```

会变成 `香港🇭🇰-01`。编辑时点 **看看结果** 可以先预览，会显示每个节点改名前后的名字和过滤掉了几个。

## 链式代理

让客户端先连 **中转节点**，再经它连 **落地节点**，网站看到的是落地节点的 IP。适合“国内 → 香港中转 → 美国落地”这类线路，或者给机场节点套一层自己的落地。

在订阅的 **链式代理** 里填两个名称表达式（写法同“名称包含”）：

- **落地节点**：匹配到的节点挂上中转组，即 Clash / Mihomo 的 `dialer-proxy`、sing-box 的 `detour`、Surge 的 `underlying-proxy`
- **中转节点**：匹配到的节点放进“中转节点”组

也可以 **按来源设角色**：在链式代理的「按来源」里，把整个订阅源设成 **不用 / 落地 / 中转**，机场改名、增删节点会自动跟上，不用再逐个对名字；再打开 **自建节点全部作落地**，自己的节点就都走这条链。按来源设了角色后，名称表达式会被忽略（界面有提示）。订阅源标了用途（见上）的话，新建订阅时角色已经自动带好。

生成的订阅里多两个分组：

| 分组 | 说明 |
|------|------|
| 落地节点 | 选出口，排在“节点选择”的第一个 |
| 中转节点 | 选中转，所有落地节点都经这里选中的节点连接 |

```yaml
proxies:
  - name: "美国 落地 01"
    type: vless
    # ...
    dialer-proxy: "中转节点"
```

- 两项都填且都匹配到节点才生效；同时匹配两项的节点算落地
- 注意失效情形：同时匹配两项的节点算落地，所以如果中转表达式唯一能匹配到的节点同时也被落地表达式命中，中转侧就没有可用节点，整条链不会生效——预览和拉取里都不会出现链式分组，目前也不会给出警告。配置时请让中转侧至少保留一个只命中中转表达式的节点
- 匹配的是改名后的名字，也认原名；预览里会标出“落地”“中转”
- 落地节点仍可在“节点选择”和地区分组里直接选，选中后同样经中转连接；中转节点也可以单独使用
- 通用分享链接（Base64）无法表达链式，落地节点在里面是直连
- 延迟叠加，速度取决于最慢的一段；落地是 Hysteria2 / TUIC 等 UDP 协议时，中转节点要能转发 UDP

> 这是客户端侧的链式。想让服务器自己把流量转到另一个节点出去（客户端无感），用入站的 [出站](./nodes.md#出站)。

## 规则与脚本

订阅编辑页的 **规则与脚本** 区提供两项进阶能力：分流规则引擎和自定义改名脚本。

### 分流规则

打开 **分流规则** 开关，并勾选需要的规则分组：

| 规则组 | 说明 |
|--------|------|
| 广告拦截 | 拦截广告域名（REJECT） |
| AI 服务 | 优先走美国节点 |
| YouTube / Netflix / 国外媒体 | 媒体解锁走代理 |
| Telegram / Google | 走代理 |
| 微软服务 / 苹果服务 / 游戏平台 | 直连 |

开启后各客户端的输出变化：

| 客户端 | 开启规则后的输出 |
|--------|------------------|
| Clash / Mihomo | 配置含策略组（`proxy-groups`）和规则（`rules`） |
| Stash | 配置含策略组和规则（规则集为 YAML 格式，不含 Mihomo 的 DNS / 嗅探设置段） |
| sing-box | 配置含路由规则和规则集 |
| Surge | 配置含自动选择策略组与规则，输出完整配置 |
| Loon / Quantumult X / Shadowrocket | 输出**完整配置**（含策略组、规则、DNS），而不是纯节点列表 |

只开分流规则、没开「按地区分组」时，Clash / sing-box 输出里仍会附带地区分组（规则的落点需要地区组），这是预期行为。

> 规则分组名会预留，不会和节点重名冲突。规则源来自 MetaCubeX 和 blackmatrix7 的公开规则集，需要节点能访问外网以下载。

### 自定义脚本

用 JavaScript 给节点批量改名，适合改名规则表达不了的逻辑。

- 在 **自定义脚本** 文本框里写 `operator(nodes)` 函数；脚本里能看到每个节点的 `id`、`name`、`original`（原名）、`server`、`port`、`protocol`、`region`、`line`；逐字段层面只有 `name` 的改动会被采纳，但脚本**返回的数组决定最终的节点集合与顺序**——从数组里去掉的节点会被过滤、调整数组顺序即完成排序
- 运行在 goja 沙箱里：无网络、无文件、无定时器；`console.log` 可用
- 单次执行 1 秒超时：死循环脚本会被终止，编辑器会显示错误
- 脚本上限 20000 字符，超长会被拒绝
- 脚本执行失败不影响改名规则等其他步骤的结果

## 独立凭据

- 每个订阅有自己的 UUID / 密码，和你的凭据同时写进节点配置，互不影响
- **停用**、**删除** 或 **到期** 后，面板会把它的凭据从节点上删掉，已导入的配置也连不上了；但共用凭据的节点例外（Shadowsocks、Snell 和导入的节点，见下一条说明）：删除订阅只删链接、共用密码不变，对方已经导入的配置仍能连接
- **重置链接和凭据**：旧链接和对方已导入的配置立即失效，适合链接泄露时使用；但共用凭据的节点例外（Shadowsocks、Snell 和导入的节点）：它们用的是共用密码、重置不轮换，重置后对方已经导入的配置仍能连接，要断开只能改对应入站的密码
- 支持单独凭据的协议：VLESS、VMess、Trojan、Hysteria2、TUIC、AnyTLS、NaïveProxy。Shadowsocks、Snell 和导入的节点只能共用原来的密码：停用后订阅失效，但对方已经导入的配置仍能连接（界面上会标出“共用凭据”）
- 例外：Shadowsocks 2022 入站可以开启「按订阅计量」（见下文同名小节）。开启后订阅新拉取的配置改走独立凭据并计入流量统计与流量上限；开启前已分发的链接照常可用，但不计量
- 3 天内到期会推送 [通知](./notify.md)

### 流量上限

- 每个订阅单独统计流量（上传 + 下载），可以设 **流量上限**，用完自动断开，和到期一样
- **每月重置**：选每月几号，到那天 0 点自动清零；也可以在订阅详情里点 **重置流量** 手动清零，超限断开的会立即恢复
- 用到 90% 和用完时会推送 [通知](./notify.md)，概览页的“需要处理”里也会列出
- 客户端里能看到已用流量、总量和到期时间（`Subscription-Userinfo`）
- 统计在落地节点上进行：每个订阅走自己的出站，节点用 nftables 计数，Xray 和 sing-box 都支持。需要节点上有 nftables，并且节点 agent 要和面板一起更新到最新版（旧 agent 能正常转发，只是不计数）
- 只统计支持单独凭据的协议。共用凭据的落地（Snell、导入的节点，以及未开启「按订阅计量」的 Shadowsocks）分不清是谁在用，不计入

### 流量统计

订阅详情里有 **流量统计**：按小时（近 24 小时）、日（近 30 天）、月（近 12 个月）看这条订阅的上传、下载曲线。被分配了这条订阅的用户，在 **我的订阅** 里展开自己的订阅卡片也能看。

- 曲线是 **整条订阅的合计**：一条订阅分给多人时，凭据是同一套，流量拆不到个人，每位被分配用户看到的是同一条合计曲线
- 统计口径和「已用」一致（只统计独立凭据协议与已开启计量的 Shadowsocks 2022，共用凭据不计入）
- 详情与「我的订阅」会标注统计的**起算时间**（订阅创建或上次重置流量之时），显示为「<日期> 起已用 …」；重置流量后起算时间随之更新，起算之前的时段不在统计内
- 自 1.3.0 起开始记录，上线之前的时段没有数据
- 小时级统计数据保留 400 天，更早的数据会被自动清理

### Shadowsocks 按订阅计量

Shadowsocks 原本是共用凭据，分不清每条订阅的流量。自建的 Shadowsocks 2022 入站可以在编辑入站时开启「按订阅计量」：

- 开启后，面板在**同一节点**上为该入站生成一个计量专用入口（入站列表会显示「计量中」徽标）。订阅**新拉取**的配置自动改走这个入口并使用独立凭据，流量计入该订阅的统计与流量上限，和其他独立凭据协议一样
- **已有链接不受影响**：开启前分发的配置继续连原入口、照常可用，但不计量；想纳入计量，让使用者重新拉取一次订阅即可
- 订阅停用 / 删除 / 到期 / 超出流量上限后，计量入口上的对应凭据会照常被移除，重新拉取的配置随之断开
- 仅支持 2022 系列方法（如 `2022-blake3-aes-128-gcm`）。传统方法（如 `aes-256-gcm`）、ShadowTLS 前置的入站、Snell 和导入的节点没有多用户能力，不在覆盖范围内
- 注意：持有共用密码的人仍可直连原入口绕过计量与上限（与开启前一致）。要彻底收口，可在大家重新拉取后更换原入站的共用密码——原密码分发的配置会随之失效，计量入口不受影响

## 分配给用户与撤销

管理员可以把订阅分配给指定用户（订阅分配），被分配的用户在自己的「我的订阅」里能看到并复制该订阅的链接。

撤销时注意链接的认凭据方式：**订阅链接认的是订阅本身的 token，不认人**。

- 删掉某个用户的分配、禁用或删除该用户：只是让他在面板里看不到这个订阅，**他此前已经复制走的链接仍可继续拉取使用**
- 要断掉某个人已复制的链接，只能 **重置订阅**（链接和凭据一起轮换，旧链接立即失效）或 **删除订阅**；两者都会同时影响该订阅的全部持有者，无法只断一个人
- 停用订阅或订阅到期、流量用完：对全部持有者立即生效，链接拉取直接被拒

## 其他

- 点订阅可以导入到客户端、复制各种格式的链接、编辑、重置链接或删除
- 所有订阅都包含在 **网站配置 → 数据备份与恢复** 的“内核与入站”里
- 订阅当前没有可用节点时（节点全停用、被过滤光或订阅本身为空），拉取返回 HTTP 200 和一份**空节点列表**，而不是错误码——这是刻意的：返回 503 会被客户端当成订阅源故障并保留旧节点，返回空列表能让客户端及时清空

## 联邦远端用量的统计口径

把节点通过联邦分享给其他面板使用时，面板记录的远端用量是**提供方节点实际消耗的物理流量**（上传 + 下载的原始字节数），不乘本地隧道的流量倍率（TrafficRatio），也不按本地的配额口径折算。

因此，远端用量与消费方面板按其倍率、配额算出的计费数字**口径不同、不能直接对账**。不要直接用远端用量数字做本地计费判断；判断某个分享是否超量，以该分享自己设置的流量上限为准（上限同样按物理流量计算）。
