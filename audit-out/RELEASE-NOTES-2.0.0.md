# FLMX 2.0.0 发版说明

1.9.9 基线全量审计收官版：24 分区全仓审计（143 条次 → 133 根）＋逐根修复＋换位复审（14 路、无人复审自家分区）＋非作者红证复验＋真机验证，终局 **零 P0、零 P1**，P2 全部已修或书面转决策，P3 绝大多数已修或文档关闭。本版另含审计收尾的五项决策落地（WS 短期票据＋登出吊销、MD5 sunset＋JWT_SECRET 告警、信封契约成文、C2-03 书面豁免、校验锚分层确认）。完整账目见 `audit-out/AUDIT-REPORT.md`。

## 修复要点

- **11 条 P1 全部修复并三重验证**（复审＋红证＋真机），含：面板升级的 PG 卷比对与回滚收口、备份恢复的分享地址与管理员状态面、订阅下发校验、agent 命令通道认领集、内核安装 TOFU 校验等。
- **复审新发现的 4 条 P2、17 条 P3 已同批复修**（导入可停用唯一管理员、升级卷探针失败放行、安装脚本第二锚接受代理自证、联邦 `netns` 资源键漏网族等），并经非作者回退红证逐条验证（回退即红、恢复即绿）。
- **下载与升级校验全链收口**：面板、agent、安装脚本、内核与 geodata 五面的校验和锚统一为「校验必备、fail-closed」，同源自证不再被当作独立佐证。
- **真机验证随行**：面板双库（SQLite＋PostgreSQL）场景批、agent 五组双树对照、脚本套件容器隔离全套（215 例）在修复后逐批复跑通过；PG 契约 10/10 实跑通过（含 ICU locale 大小写折叠例）。

## 新增与改进

- **浏览器实时通道票据化**：前端连接节点实时通道（监控/延迟推送）前先以登录态换取 **30 秒单次票据**，长效登录令牌不再出现在 WS 连接链接里（详见 BC-3）。
- **服务端登出吊销**：点登出即在服务端吊销此前签发的全部令牌（详见 BC-3）。
- **JWT_SECRET 弱密钥启动告警**：启动时对缺失/过短/低熵的 `JWT_SECRET` 打具名警告（详见 BC-4）。

## 行为变更（BC）与升级须知

1. **升级/下载校验锚分层：代理线路无佐证时由降级放行改为拒绝（拒绝面）**。面板内升级、agent 自升级、生成的安装命令、内核与 geodata 安装四面统一分层：直连或注册面板源（第一方）获胜且复核不可用时，保留「点名降级」放行并回执点名；**第三方代理获胜且拿不到异路校验值佐证时，硬拒绝并在回执里点名原因**（旧行为是点名降级后照常下载）。影响面仅限「直连已死、只剩单个代理活着」的网络态；运维退路不变：脚本升级可显式单线、或手动替换产物。被拒绝时先恢复任一第一方线路再重试，不要关校验。
2. **存量 MD5 密码账户 sunset**。仍以无盐 MD5 存放密码的休眠老账户**不再验密放行**：这类账户在升级后首次登录会被收口为终态（密码置为随机 bcrypt、账户停用、既有会话吊销），须由**管理员在用户管理里为其重置密码**后重新启用登录；想自助改密的 legacy 账户同样 fail-closed、走管理员重置。正常 bcrypt 账户零影响。`security.MD5` 接受面已整体删除，此后没有任何入口再接受 MD5 口令校验。
3. **WS 票据化＋登出吊销**。浏览器 WS 握手只认 30 秒单次票据、不再接受链接里的裸登录令牌；前端每次（重）连前自动取票，用户无感知，**但升级后须刷新已打开的面板页面**（旧页面内嵌的旧连接方式会连不上实时通道，刷新即恢复）。登出改为服务端吊销：点登出后，该账户此前签发的全部令牌立即失效、已建立的浏览器实时连接随 keepalive 复检关闭；不要求改密，重新登录正常使用；其他用户不受影响。节点（agent）通道走节点密钥、不在此列，未做任何改动。
4. **JWT_SECRET 弱密钥只告警、不拒启**。`JWT_SECRET` 缺失、长度 <32 字符或明显低熵时，后端启动日志打具名警告 `WARN JWT_SECRET_WEAK` 并写清风险与改法；达标则静默。升级不会因密钥弱被拒，但请尽快轮换为 ≥32 字符随机串（轮换后全部现存登录态失效、需重新登录，属预期行为）。
5. **旧仓镜像双推在 2.0.0 为最后一版，2.0.1 起停推**。改名过渡期的旧仓双推窗口（1.9.9＋2.0.0 共两版）到本版关闭。仍从旧仓拉取面板镜像的部署请在 2.0.0 周期内切到新仓（`ghcr.io/iiiiiiiii7125-art/flmx-*`），2.0.1 起旧仓不再有新版镜像；节点 agent 与脚本分发不受影响。
6. **`FLVX_*` 环境变量双读在 2.0.0 退场**。1.9.8 改名过渡期引入的旧名双读（`FLVX_*` 兜底）自本版起只认新名 `FLMX_*`；仍在用旧名键的部署，升级后旧名键会被**静默忽略**、对应功能回落缺省（如可信代理跳数回默认 1、私网放行名单失效、Passkey 按未配置处理等），不报错——请在升级前按 `doc/guide/upgrade.md` 的对照表逐项改名（9 个键，只换键名、值不变，并确认 compose 有新名传递行）。`FLUX_VERSION` 版本键不在此列：仍新旧双写、旧名回退读取，长期并存，不用改。
7. **API 信封契约成文（无行为变更）**。业务响应恒 HTTP 200＋`{code, msg, data}` 信封、以前端消费的 `code` 判失败，是既定契约而非缺陷，本版起写入 `doc/guide/faq.md` 点名定稿；少数机器端点（订阅拉取、健康探针等）的真 HTTP 状态语义不变。
8. **C2-03 书面豁免（无行为变更）**。sing-box 远程 rule-set 的格式本身没有可填的完整性字段，URL 为固定模板＋闭合标签集；本版在审计报告增补节（§9）书面豁免并登记残余风险边界与复议条件，分流规则的生成与下发行为不变。

## 升级路径

- 面板内升级、脚本升级两条既有路径不变；升级前 DB 快照＋升级后双卷比对的自动回滚保护保持。
- 升级前自检三项：①`FLVX_*` 旧名键改名（见 BC-6）；②`JWT_SECRET` 长度（见 BC-4，弱只告警不拦）；③若部署在「仅代理可达」网络，确认至少一条第一方线路可达（见 BC-1）。
- 升级后：刷新已打开的面板页面（见 BC-3）；若有 MD5 存量账户，通知管理员走重置流程（见 BC-2）。
