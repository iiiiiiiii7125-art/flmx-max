流量转发与管理 ​

面板保留了原有的转发面板功能：多用户、端口转发和隧道转发、配额与限速。

术语对照：面板菜单与中转页里的 规则 标签就是本文档所说的转发 / 转发规则。

仪表盘 (Dashboard) ​

登录系统后首先看到的是仪表盘，这里展示了系统的整体运行状态，包括：

  • 在线节点数量与节点状态
  • 内核、入站、中转、订阅概况与告警
  • 流量统计信息（总流量 / 已用流量 / 规则配额与流量图）

用户总数不在仪表盘展示，在用户管理页可查。

节点管理 (Node) ​

节点是实际承载流量转发的服务器。

  • 添加节点: 点击“添加”，获取密钥用于节点端安装。
  • 管理: 可以查看节点在线状态、版本信息，以及对节点进行编辑或删除。

用户管理 (User) ​

管理员可以创建和管理普通用户。

  • 创建用户: 设置用户名、密码、流量配额等。
  • 用户组: 可以将用户分配到不同的组 (Group)，便于统一管理权限或策略。

日/月配额 ​

除总量流量限额外，每个用户还可设置日配额（每天可用流量）与月配额（每月可用流量）：

  • 用量按自然日 / 自然月窗口累计，窗口滚动后用量自动清零。
  • 任一档用量达到限额时，该用户的转发会被暂停（新转发也无法开启）；窗口滚动或管理员手动重置用量后，暂停的转发自动恢复。
  • 通知：用量达到限额 90% 时发一次预警，用完时发一次用完通知；配额解除（窗口滚动或手动重置）后发一条恢复通知。同一问题只提醒一次，用量回落后再超额会重新提醒。详见通知。
  • 每日汇总里会列出当前日/月配额超额的用户数（无超额时不显示该行）。

转发管理 (Forward) ​

这是核心功能区，用于设置端口转发规则。

  • 端口转发: 将节点服务器的某个端口流量转发到目标地址。
    • 协议: 支持 TCP / UDP。
    • 入口: 选择入口节点和监听端口。
    • 出口: 设置目标 IP 和端口。
  • 隧道转发: 流量经隧道在节点之间穿透，包括“前置 → IX → 落地”多跳线路，见 对接中转。

转发引擎（realm） ​

端口转发隧道（类型为端口转发）可在创建/编辑时选择转发引擎：

  • 面板转发（默认）：由节点 agent（gost）直接转发，功能最全，支持转发级限速与连接数限制。
  • realm：由独立的 realm 程序在入口节点上转发，资源占用低。面板会像管理内核一样在入口节点自动安装、监督 realm（一台节点一个 realm 实例，配置为该节点上全部 realm 转发）。

使用 realm 的限制：

  • 仅支持端口转发隧道；入口节点不能是远程节点，也不能是 nftables 转发模式；节点 agent 需为支持 realm 的版本。
  • 不支持转发级限速和连接数限制：转发上设了限速/连接数时，同步会给出警告并忽略这两项。
  • 负载策略只支持轮询（round robin）与 IP 哈希（hash）。

使用 nftables 转发模式的限制：

  • 不支持限速和连接数限制：转发上设了限速/连接数时，同步会给出警告并忽略这两项。
  • 单入口约束：nftables 模式的隧道只支持单个入口节点；隧道编辑加入第二个入口会被拒绝，已有转发的隧道入口节点切换转发模式也会被拒绝（混合态下暂停/删除/恢复只走单入口分支，另一引擎的服务不会被触碰）；已存在的混合态请先编辑隧道去掉 nft/多余入口后再操作。

计费口径（重要）：两种引擎、两种节点转发模式（agent / nftables）的计费口径一致，没有“某引擎不计费”：

  • 流量按方向如实统计：入 = 客户端→远端，出 = 远端→客户端。转发的「已用流量」↑ 显示入、↓ 显示出。
  • 配额扣减按隧道上的计费模式执行：单向 = 只扣入方向流量；双向 = 入 + 出。之后再乘隧道的流量倍率（trafficRatio）。切换引擎（gost ↔ realm）或转发模式不改变计费口径，同一笔流量在任何引擎下入账一致。
  • 计数来源不同：面板转发（gost）由 agent 上报转发字节；realm 由节点上的 nftables 端口计数器采集；nftables 模式由面板托管的 nftables 规则计数。三者在面板侧走同一套方向与配额逻辑（含 realm 在内的引擎切换只换数据面，不换口径）。
  • 历史口径提示：1.3.1 起单向计费的方向由「按出」改为「按入」（与本节定义对齐）；该变更只对生效之后的流量起作用，历史已扣减的配额不回溯调整。
  • 切换引擎时面板先释放旧引擎的监听再拉起新引擎，不会双占端口；切换前后的流量各自按发生时的计数来源入账，不会重复计。

端口占用与复用口径 ​

  • 端口冲突只看同一节点上的同一端口：同一端口可以同时用在不同节点上，互不影响。
  • 同一节点上，转发、隧道链路与入站共用同一端口空间，分配时统一做占用校验。
  • 自定义入口端口（inPort）必须是 1–65535，且落在该节点的端口范围内，否则会被拒绝。
  • 节点的「可用端口」范围只约束转发/中转/隧道入口端口（自动分配也从中取口）；入站的监听端口不受此范围约束，只做同节点占用冲突校验。
  • 多入口转发不能自定义监听 IP（inIp）；编辑转发时不改监听 IP 会保留原 IP，切换隧道时才重置。

删除与端口回收 ​

  • gost 模式的转发删除后，节点上的监听服务随即移除，端口释放。
  • nftables 模式的转发删除走“先标记待删除（pending-delete）→ 后台对账确认节点侧规则已移除 → 删除记录”：节点离线时删除会进入 pending-delete，由后台任务按 1m / 5m / 30m / 2h 退避自动重试，上限 24h 后转人工处理；等待期间该端口仍视为占用，不会分配给新转发。管理员可通过 POST /api/v1/node/nftables/pending-deletes 查看待清理项，见 节点管理。

限制与策略 (Limit) ​

  • 限速: 可以对指定用户或指定隧道进行带宽限制，防止资源滥用。
  • 计费模式: 支持配置流量计算方式（单向或双向），适合运营场景。转发流量按入、出两个方向分别统计，配额扣减按计费口径累计。

系统配置 (Config) ​

在此页面进行系统的全局设置。

个人设置 (Profile) ​

  • 修改密码: 为了安全，建议定期修改管理员密码。
