对接中转 ​

中转 页的 线路 标签按落地列出所有中转线路，点一个落地 → 选择隧道即可添加（也可以在落地页点入站 → 中转）。隧道在 中转 页的 隧道 标签创建，入口是中转机；原来的“规则”在 规则 标签。隧道质量在 质量 标签查看。

对接方式 ​

  • 端口转发：中转机直接把流量转发到落地机的公网地址
  • 隧道转发（出口为落地机）：流量经隧道到落地机，再转发到 127.0.0.1:入站端口。入站可以只监听 127.0.0.1，落地机不对外暴露端口
  • 隧道转发（出口为其他节点）：用于“前置 → IX → 落地”这类多跳线路。流量经隧道到出口节点（如 IX），再由出口节点连接落地机的公网地址。只需要中转、不需要加密时，隧道协议选 TCP 即可

前置 → IX → 落地 ​

  1. 节点页添加前置、IX、落地三台机器，都装好 agent
  2. 隧道页新建一条“隧道转发”：入口选前置，出口选 IX，协议按需选择（不需要加密就选 TCP）
  3. 点击落地机上的入站 → 中转，选这条隧道
  4. 如果 IX 只允许前置访问，在 IX 的防火墙里放行前置的地址即可；落地机可以开启入站白名单，只放行 IX

订阅里的中转线路使用前置的地址和入口端口。

链中某一跳故障时：明确断开，不再静默绕行 ​

1.3.4 起，多跳链（隧道链 / 链式代理的节点侧链路）中任一跳的全部节点不可用时，连接会明确失败并报错（错误信息带链名，可定位是哪条链断了）：

  • 旧行为是中间跳故障时静默截断、绕过后面的跳继续走，首跳故障时甚至静默变成从本机直连出站——连接看似可用，实际出口与预期不符，还可能暴露真实出口 IP；
  • 新行为下链部分故障期间受影响的连接直接断开，链恢复后自动正常；链健康时行为与之前完全一致。

这是有意的行为变更：静默直连属于隐私事故，明确失败才可观测、可告警。如果升级后出现「链断了才发现某跳长期故障」，按报错里的链名检查对应跳的节点即可。

订阅与清理 ​

中转线路会自动加入订阅，名称为“隧道名 → 入站名”。删除中转、入站或内核时，相关的转发会一并清理。

用户分组与限速规则（用户页） ​

用户多、隧道多时，可以在 用户 页用分组批量管理分配权限：

  • 用户组 / 隧道组：把用户、隧道分别编组（用户 页 → 分组 标签）。
  • 组权限：把某个用户组授权给某个隧道组；之后给该组用户分配隧道时，可选范围就是被授权隧道组里的隧道。分组是可选的批量管理工具，不分组的用户与隧道照常逐个分配。

分组停用语义：停用用户组或隧道组时，该组发放的组建授权会被收回、对应的转发会被清理；手工单独授予某个用户的授权不受停用影响。重新启用分组后，会按当前组成员与组权限重新补发组建授权。升级前就已经停用的存量分组，其组建授权会在首次同步、或再次保存该分组时追溯收回并清理对应转发。

限速规则（用户 页 → 限速 标签）是命名的速率上限（名称 + 速率），建好后被引用才生效：

  • 转发可以分别绑一条全局限速（整条转发合计）和一条单 IP 限速（每个来源 IP 各一份）；
  • 隧道可以绑一条限速规则，作用于经该隧道的转发。

获取真实客户端 IP（仅 Xray） ​

开启后，中转转发会附带 PROXY protocol，落地机内核日志里能看到客户端真实 IP。开启后直连将无法使用，入站会自动变为“仅中转”。

入站白名单 ​

开启后，该入站端口只放行本机、直接连接落地机的节点（端口转发的中转机、隧道转发的出口节点）和你填写的额外 IP / 网段，其余来源直接丢弃，只影响这一个端口。中转增删时白名单会自动更新。

删除隧道与节点离线时的语义 ​

删除隧道不需要节点在线：在面板里删隧道会立即生效——隧道、挂在它上面的转发与用户分配在数据库里一并删除，接口直接返回成功（对已删除的隧道重复删除同样返回成功）。

节点侧监听的清理由 agent 在重连对账时完成：离线期间删掉的隧道，节点重新连上面板后会按面板的最新配置把对应监听撤掉，本机实测三方（数据库、节点监听、nft 规则）最终一致、无残留。

注意：如果节点其实没有停机、只是与面板网络分区（agent 还在运行、只是连不上），分区期间旧监听会继续按删除前的配置服务，直到分区恢复、agent 重连完成对账。介意这一点的场景，请先停掉节点 agent 再删隧道。

联邦（面板共享）升级顺序：先消费方，后提供方 ​

1.3.4 起，提供方的 middle / exit 角色服务恒带每共享独立的 relay 鉴权凭据，旧版本消费方不带凭据会被拒绝。双方版本不一致时的行为：

组合结果
新消费方 + 旧提供方正常：旧提供方不下发凭据，消费方就不带凭据连接，旧的无鉴权服务照常接受
旧消费方 + 新提供方中转链数据面不通：消费方无凭据被提供方拒绝；但控制面（连接、建隧道、状态同步）全部显示成功，面板上看不出异常——只有流量不通
双方同为 1.3.4正常，凭据自动下发与自愈

所以升级联邦双方时请按 先消费方、后提供方 的顺序：先升消费方不会产生任何断裂窗口；反过来先升提供方，断裂窗口从提供方升级那一刻就开始、一直持续到消费方也升完。无论哪种顺序，两方都应尽快升到同一版本。

版本提示（panelVersion）：1.3.4 起联邦连接（Connect）会互相携带面板版本号。消费方版本缺失或低于 1.3.4 时，提供方会在回执里给出 versionWarning 并记一条日志；消费方一侧在导入远端节点、用量同步、状态同步的回执里同样能看到对端版本与该警告。看到「对端面板版本过旧」类提示，含义就是对方还没有 relay 鉴权（或还没被鉴权保护），按上面的顺序尽快把落后的一方升上来即可。提供方若从旧备份恢复，存量共享的凭据会被重新补发，消费方在下次同步时自动自愈刷新，期间可能有短暂窗口。

联邦隧道的已知限制：对端可能残留孤儿隧道 ​

（联邦在面板菜单里叫 面板共享 / 共享，是同一功能。）

通过联邦使用对端面板的节点建隧道时，面板先在对端创建隧道、再在本地保存。如果本地保存这一步失败（例如端口冲突或数据库异常），对端已经创建的隧道不会自动回滚，对端会残留一条没有本地对应记录的孤儿隧道，并占用对端的端口。

这是已知限制，不是 bug。 管理员需要定期检查对端面板的隧道列表：发现对端存在、但本地没有对应记录的隧道时，在对端面板手动删除它。另请注意：本地保存失败后，如果直接用同一端口重试建隧道，会被对端以「Port already in use」拒绝（孤儿隧道仍占用着该端口、不会自动消失），须先在对端面板手工清理孤儿、释放端口后再重试。
